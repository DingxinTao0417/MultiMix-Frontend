# 生成图片确认布局（“先生成图片，再做视频”做法）

> Status: current
> Owner: frontend
> Last verified: 2026-10-15（改为单镜图片确认；撤销编导阶段多关键帧批量应用）

## 背景

2026-10-15 用户确认：编导阶段不生成图片供用户挑选，也不再提出“关键帧建议”。原设计中“连续关键帧组 → 逐帧审核 → 分别应用到分镜”的流程随之退役。

保留的场景只有一个：用户在确认卡中为某一镜选择“先生成图片，再做视频”。这时系统确认后先生成图片，交用户看过并确认，再做成视频。本规格只描述这一步的展示与确认。

## 已确认设计

展示区采用单列的“看图 → 检查 → 操作”顺序：

1. 顶部展示该镜生成图片的大图，标注“第 N 镜”。
2. 大图下方显示检查结果：状态徽章与镜号同一行，人工复核提醒保持一行；未发现问题时使用短提示，发现问题时最多展示三项证据。
3. 操作：`用这张做视频`、`重新生成`、`我来上传`。点“用这张做视频”后才进入视频生成；不自动生成视频。
4. 大图画布使用展示区完整可用宽度，以中心裁切展示；可通过“打开原图”查看完整图片。

## 交互与状态

- 一镜只确认一张图片；不出现多帧组、帧切换或批量应用映射。
- “重新生成”与“用这张做视频”都需经过费用确认卡，确认前不生成、不扣费。
- 图片检查未通过时仍可由用户决定重新生成或上传，不自动替换。
- 对用户只用“图片”“画面”，不出现“关键帧”等内部词。

## 响应式规则

- 宽屏和窄屏均使用单列内容顺序，检查结果不固定为右侧栏。
- 画布与检查区均使用完整可用宽度，只保留外层统一内边距。

## 验收

- 只有用户为该镜选择“先生成图片，再做视频”时才出现本界面。
- 页面不出现关键帧组、帧切换、批量应用或“分别应用到分镜”。
- “用这张做视频”之前不发起视频生成。
