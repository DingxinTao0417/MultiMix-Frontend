# 视频任务进度卡

> Status: current
> Owner: frontend
> Last verified: 2026-09-15

## 1. 目的与适用范围

普通商家只需判断任务是否正常进行、是否需要自己操作，以及结果是否可用。视频方案准备、视频制作、视频修改统一使用紧凑进度卡。

用户于 2026-09-15 在“优化视频生成进度卡”会话确认：视频全流程、展开后少量关键进展、真实阶段与可离开提示、成功后一行保留。本规范取代上述视频范围原有“固定标题、默认展开、第几步/共几步、逐步计时”的展示要求。

- 独立图片、文案、上传与导出进度保持现状。
- 不新增预计剩余时间、等待计时、百分比、完成通知或自动重试。
- 不改变确认门、任务幂等、来源合同、费用判断或视频完成谓词。
- 实施与验证记录见[跨端计划](../../../../MultiMix-Backend/docs/plans/active/2026-09-15-video-progress-card-simplification.md)。

## 2. 默认卡片

执行中默认显示当前状态、一句说明和“查看进度详情”。必要操作不受详情展开状态控制。

| 场景 | 当前状态 |
| --- | --- |
| 请求尚未确认持久化 | 正在提交任务 |
| 后台已排队 | 视频任务已提交 |
| 视频方案准备 | 正在准备视频方案 |
| 视频制作 | 正在制作视频 |
| 视频修改 | 正在修改视频 |
| 视频方案完成 | 视频方案已准备好 |
| 视频制作完成 | 视频已做好 |
| 视频修改完成 | 视频已更新 |
| 用户主动停止 | 本次任务已停止 |
| 读取状态失败 | 暂时无法更新进度 |
| 方案/制作/修改失败 | 视频方案未完成 / 视频制作未完成 / 本次修改未完成 |

只有后台任务已经持久化，才提示“你可以先离开本对话，稍后回来查看”。提交尚未确认时不显示可离开承诺。进度读取失败显示重新连接说明，保留最后一次真实进展。

完成后只保留状态与展开入口；查看、修改、确认和导出继续由结果卡承担。方案完成不等于视频完成。

## 3. 详情与展开规则

每张卡最多四个产品阶段：

- 视频方案：任务已提交、整理资料、准备视频方案、方案已准备好。
- 视频制作：任务已提交、准备画面、制作视频、视频已做好。
- 视频修改：任务已提交、调整内容、视频已更新。

未发生的阶段省略，不展示未来等待步骤。内部分析、核对、修补与技术重试按稳定事件键归并。未知事件使用本任务的通用工作阶段，不直接显示原始标签。

- 初次进入和刷新后详情默认收起。
- 推进、失败、重试不强制改变用户选择。
- 成功自动收起一次；之后手动展开不再次强制收起。
- 原始历史仍持久化，但普通卡片不提供技术日志入口。
- 没有历史事件时只展示能够证明的提交、当前工作或终态；不能补写执行过程。

## 4. 失败、操作与结果一致性

- 失败原因和必要操作始终可见，禁止只放在折叠详情中。
- 消费服务端安全错误，保留准确的任务/子任务/动作 ID；不能从合并阶段推断重试对象。
- 仅展示已有且允许的重试、重新生成、停止、修改方案或替换画面入口。
- 要求修改脚本或更换素材时，不提供无效的盲目重试。
- 主工程内部 ready 后仍有必要画面、声音或动效未完成时，视频保持生成中。
- 修改任务失败只表示本次修改未完成，上一稳定视频继续可用。
- 可选工作告警不能覆盖服务端已经确认的交付状态；必要工作失败不能被其他运行中分支掩盖。
- 停止使用中性状态，不显示为成功或报错。
- 网络错误不代表任务失败，不触发重新创建或付费执行；使用已有轮询恢复。
- 刷新、重试和断线恢复复用同一张卡，不新增平行任务卡，不改变对话顺序。

## 5. 确认卡与卡片视觉

原确认卡保留为已确认工作对象，进度卡紧随对应控制事件；不伪造用户确认气泡，不重复显示排队助手正文。

- 确认卡与进度卡共享桌面最大宽度 560px；窄屏等宽收缩，不横向溢出。
- 保留白色主题卡片、1px 主题边框、16px 圆角和既有柔和阴影。
- 标题使用现有 12px 层级；次级说明 12px，自然换行，无固定高度。
- 完成、失败、停止使用图标与文字共同表达；运行使用现有 AI 状态动效。
- 关键进展保留共同状态列，不显示逐步耗时或步骤计数。
- 本次不调整播放器外壳、画布比例、底部控件或展示区布局。

## 6. 数据与组件边界

- 内容生成任务的可选 progress_kind 为 video_plan、video_create、video_update 或 general。服务端按持久化结构化目标投影，实时响应与会话记录一致。
- 旧记录可使用已绑定产物类型或明确视频事件键识别；无法确认用途时保留旧卡。不得解析用户文字或显示标签来判断用途。
- 任务生命周期决定状态，产品阶段只解释进展。不能以列表全部打勾、步骤数量或经过时间推导完成。
- VideoProgressCard 与 video-progress-presentation 承担视频摘要。AgentRunTimeline 保留给本次范围外的内容生成。
- 主壳和任务 hook 继续负责轮询、提交对账、版本刷新及准确操作绑定；组件不建立另一套任务状态机。

## 7. 无障碍与验证

- 展开按钮使用 aria-expanded/aria-controls；状态区域使用 polite 播报，只播报产品状态变化。
- 成功收起不抢走键盘焦点；详情中不放关键动作。
- 减少动效偏好下关闭运行动画；状态不能只靠颜色表达。
- 验证默认折叠、关键阶段上限、未知事件、失败与运行并存、终态对账、停止、重试准确 ID 和可选告警。
- 浏览器覆盖方案/制作/修改、刷新、切换对话、断线恢复和完成收起；保留桌面与窄屏截图。
- 独立图文、上传、导出与播放器继续运行既有回归；不得用改写测试放宽完成或视觉合同。
