# MultiMix 对话加载与回复动效设计

> Status: current
> Owner: frontend
> Last verified: 2026-07-12

## 1. 目标

让用户能一眼区分“正在读取已有对话”和“助手正在生成新回复”，同时减少跳点动画带来的临时占位感。动效只说明真实状态，不展示后端没有提供的伪阶段。

## 2. 范围

本设计只覆盖对话区的两种短时反馈：

- 历史对话详情加载
- 助手回复等待与正文出现

不改动对话编排、消息数据结构、视频执行时间线、产物生成进度或后端流式能力。

## 3. 历史对话详情加载

当用户进入尚未加载详情的历史对话时，对话区显示消息骨架，而不是助手消息和跳动圆点。

- 骨架由 2–3 组消息轮廓组成，左右宽度不同，以表达正在恢复既有消息。
- 轮廓使用中性灰，不使用 AI 渐变，避免把数据读取误解为助手生成。
- 骨架顶部或首组轮廓旁显示小号状态文案“载入对话…”。
- 动画只做低幅度透明度呼吸，周期约 1.6 秒，不做上下弹跳。
- 加载完成后骨架淡出，真实消息在相同内容区域出现，避免明显布局跳变。
- 加载失败继续沿用明确错误文案和“重试加载”入口，不长期停留在骨架状态。

## 4. 助手回复等待

用户发送消息后，在真实助手消息位置插入一条轻量占位消息：

`✦ 正在整理内容 ···`

- 占位消息沿用助手消息的头像与左侧对齐方式，不增加独立卡片或大块边框。
- sparkle 图标和省略点只做轻微透明度呼吸；位移最多 1px，周期约 1.6 秒。
- 后端尚未提供真实阶段事件时，文案固定为“正在整理内容”，不得轮播“理解需求 / 查找素材 / 组织回复”等伪进度。
- 如果消息已经有真实执行步骤，则继续使用 Agent 执行时间线；普通等待占位不与时间线重复出现。
- 收到完整回复后，占位消息原位替换为正文。未来接入真实流式输出后，可在首段正文到达时直接移除占位并开始显示正文。
- 请求失败时，占位立即退出，显示现有失败状态或重试入口。

## 5. 时间与动效规则

- 等待状态持续不足 500ms 时不显示动画，减少快速请求造成的闪烁。
- 一旦显示，建议至少保留 300ms，再过渡到真实内容，避免视觉抖动。
- 呼吸动画的透明度建议在 0.35–0.75 之间变化；不使用明显缩放或 2px 以上位移。
- `prefers-reduced-motion: reduce` 下取消循环动画，保留静态骨架、图标和状态文案。
- 动效不得抢过正文、确认卡或产物区生成状态的视觉优先级。

## 6. 状态边界

| 前端状态 | 呈现 | 不应呈现 |
|---|---|---|
| 对话详情尚未返回 | 中性消息骨架 + “载入对话…” | 助手头像、AI 渐变、回复跳点 |
| 普通助手请求等待 | 助手占位消息“正在整理内容” | 历史消息骨架、伪阶段轮播 |
| 已有真实执行步骤 | Agent 执行时间线 | 重复的普通等待占位 |
| 请求失败 | 错误文案 + 重试入口 | 无限循环加载动画 |
| 已有正文 | 正常助手消息 | 遗留的等待圆点 |

## 7. 验证案例

- [ ] 打开未缓存详情的历史对话时，出现 2–3 组中性消息骨架和“载入对话…”，不出现助手跳点。
- [ ] 历史对话加载成功后，骨架被真实消息替换，内容区没有明显纵向跳动。
- [ ] 历史对话加载失败后，动画停止，并显示“对话内容加载失败”和“重试加载”。
- [ ] 发送普通消息且等待超过 500ms 时，助手位置出现“正在整理内容”的轻量占位。
- [ ] 回复完成后，占位原位替换为正文，不残留圆点或重复消息。
- [ ] 有真实 Agent 执行时间线的消息不再额外显示普通等待占位。
- [ ] 快于 500ms 的回复不闪现等待动画。
- [ ] 开启系统减少动态效果后，加载与回复状态保持可理解，但没有循环动画。

## 8. 实施边界

预计只需要调整对话展示组件、对应样式和前端组件测试。不得为了本动效修改后端接口、对话状态机或视频执行状态，也不得引入虚假的进度事件。
