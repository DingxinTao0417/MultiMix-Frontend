不占左侧：四个按需出现的导航方案

把导航从常驻左栏改成按需出现的浮层。四个样本的工作区都是全宽双栏， 差别在于导航从哪里来、用什么形态、以及代价是什么。

好消息：覆盖式导航的技术底子已经有了。
代码里已有完整的浮层导航实现——遮罩、Escape 关闭、Tab 焦点隔离、关闭后焦点归还 （assets-workspace-client.tsx:903 起，use-dialog-focus-management.ts）， 现在只在 ≤1180px 窄屏生效。桌面改用浮层主要是放开触发条件和重做触发入口，不需要从零造无障碍逻辑。
真正的代价不在技术，在被动感知：项目的「生成中 / 待确认 / 需处理」现在扫一眼就知道，收进浮层后必须主动打开才能看到。

本页为设计选型稿，未修改产品代码。四个样本按真实 CSS 比例还原，工作区已叠加 B 方案的成片侧改动。

1四个方案（工作区全宽，导航按需出现）

每个样本都画成「浮层已打开」的状态，方便看清导航内容；关闭后工作区即为全宽双栏。

N4 · 悬浮迷你轨

左侧一条脱离布局的悬浮胶囊（约 26px，浮在内容上不占列宽），点击展开为浮层面板。

代价
  • +
    导航位置仍在左侧，肌肉记忆不变
  • +
    不占布局列宽，工作区实际全宽
  • −
    图标无文字，四库靠猜；这正是我上一轮批评过的「靠悬停才知道是什么」
  • −
    悬浮元素会盖住内容，长文案和分镜卡需要避让
  • −
    既不如 N1 清楚，也不如 N2 干净，两头不靠

3建议

推荐 N1 顶栏项目切换器，⌘K 作为附加加速器

  1. 顶栏左侧常驻「当前项目名 ▾」，点击下拉出「新建项目 + 搜索 + 最近项目 + 资源库」。 位置感和创建动作都保住，列表按需出现。
  2. 待处理项目数做成切换器上的角标。这是无侧栏方案里最关键的一笔： 不打开面板也知道有几个项目在等你，补回被动感知。
  3. AI 后台状态移到顶栏右侧，仍遵守渐变纪律，无任务时整条隐藏。
  4. ⌘K / Ctrl+K 指向同一个面板，熟练用户可以跳过点击。它是加速器，不是唯一入口。
  5. 复用现有浮层无障碍逻辑（遮罩、Escape、焦点隔离、焦点归还），只把触发条件从窄屏放开到桌面。
需要你明确批准的两点：
一、这比弱化侧栏改动大得多。工作台设计第 3 节写明桌面是「左侧导航 + 对话区 + 展示区」三区、 `>1180px` 时左栏固定 264px；V3 规范第 4 节也把三栏 grid 定为骨架。去掉左栏等于改这两条已确认结构， 并要同轮更新：工作台设计、V3 规范、七屏原型（全部含侧栏）、实现、截图基线。
二、「单独的窗口」我按应用内浮层理解。如果你指的是操作系统级的独立窗口（像 PS 的工具面板那样可拖到另一个屏幕）， 那是另一个量级的工程，当前 Web 工作台不具备该能力，需要单独评估。请确认是哪一种。

4与弱化侧栏（S2）的取舍

  • 相同
    两条路都能让视觉重心回到成片。S2 靠减重，N1 靠移走。
  • 差异
    被动感知是真实损失。S2 下你扫一眼就知道哪个项目在生成、哪个待确认； N1 要靠角标数字提示，知道「有 2 件事」但不知道是哪两件。多项目并行的商家对此敏感。
  • 差异
    改动量差一个量级。S2 主要是 CSS 加一处结构调整； N1 要改已确认的三区布局，并同步七屏原型和截图基线。
  • 建议
    如果你想先看效果再决定，可以把 N1 做成可切换的导航模式， 默认保持侧栏，顶栏提供「收起导航」。这样不推翻已确认结构，也能真实体验全宽工作区，验证后再定是否转为默认。 代价是两套导航要同时维护一段时间。

你选定方向后（S2 / N1 / N1 可切换模式），我把 B 与导航改动合并写入 MultiMix-Frontend/docs/plans/active/，登记开发占用，再开始改代码。
