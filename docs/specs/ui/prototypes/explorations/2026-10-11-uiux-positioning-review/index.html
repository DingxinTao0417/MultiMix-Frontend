MultiMix UI/UX 与定位契合度审查

对照已确认定位「对话式 AI 短视频创作工作台 —— 把需求做成视频，再像给同事提意见一样把它改好」， 检查当前界面是否把这句承诺表达出来，并给出三个布局/交互方案与推荐。

结论：骨架契合，第二句承诺没有被界面表达出来。
「从需求到成片」这条链路的界面已经扎实：对话驱动、产物卡切换、单一展示区、真实进度、失败恢复都在。 但定位的差异化重心是后半句「不满意的地方接着聊、局部改」——当前它在界面上默认不可见： 逐镜修改入口写成 hover 才出现，版本对比与恢复藏在详情层，用户看到的成片更像「一个结果」而不是「一个可以改的作品」。 这不是美观问题，是把最难复制的能力藏起来了。

审查范围：定位规格、工作台设计、V3 设计规范、终稿原型七屏、前端实现（globals.css 12527 行 + assets 组件层）。 未覆盖：未启动真实后端，无浏览器端到端复现；本页问题均为静态代码与原型证据，标注为「已确认」的指代码事实，不代表已做用户测试。

2已确认问题

按项目审查标准分级。P0 = 阻塞核心价值传达，P1 = 明显错配，P2 = 可排期。

P0 / P1 — 需要本轮解决

  • P0
    逐镜修改入口默认隐藏。 globals.css:10242 display:none，仅 :hover/:focus-within 显形 （segment-cards.tsx:168）。定位把「局部改」列为第三层核心卖点，但新用户在成片页看不到任何可改的迹象。 商家不会猜到要把鼠标悬到卡片上。
  • P0
    成片页没有表达「这是可以改的作品」。 展示区顶部只有 详情/编辑/导出/保存 四个通用按钮，语义是「处理这个文件」， 不是「告诉我哪里不对」。定位主张的后半句在最该出现的屏幕上缺席。
  • P1
    增量执行价值不可见。 修改完成只说明「已更新」，没有「第 2 镜已重做，其余 3 镜原样复用」这类表达。 这是文档列为核心技术壁垒的能力，用户完全感知不到。
  • P1
    版本对比埋得过深。 product-preview.tsx:715 的「单视频 / 版本对比」是验收修改成果的关键视图， 但它只在已有上一稳定版本时作为次级切换出现，且首次进入保持中立不选中，用户很难发现它。

P2 — 可排期

  • P2
    原型内部口径不一致。 library.html 仍是旧侧栏（「新建对话」+ 列表式四库 + 「对话列表」）， start.html 与实现已统一为「新建项目」+ 最近项目 + 2×2 资源库宫格。 原型是视觉验收基准，现在两份互相矛盾。
  • P2
    起始页主标题与原型不一致。 实现为「新建视频项目」（conversation-start.tsx:267）， 原型为「今天想做什么短视频？」。后者更贴合对话式定位，但文档未记录这次收敛，无法判断是有意决策还是漂移。
  • P2
    生成态「AI 在参与」的视觉未落地。 V3 规范第 5.3 节的产物区极光、打字光标、实时引用亮框在 CSS 中查无实现。 规范已给降级路径，不算违规，但「过程即品牌」这条原则目前只靠时间线单独承担。
  • P2
    单文件体量影响后续改动安全性。 assets-workspace-client.tsx 214k、product-workspace.tsx 137k、 globals.css 12527 行。不是体验问题，但本轮任何布局改动都会落在这几个文件里，回归成本高。

3应保留的部分

以下已确认有效，方案不得破坏。

  • 保留
    渐变纪律。AI 渐变只在「AI 正在参与」时出现，确认卡是唯一渐变描边卡。这是产品性格的主要载体。
  • 保留
    真实进度，不做假。无服务端数据就不显示百分比和预计时间，未知事件合并进当前阶段。
  • 保留
    单一展示区，无一级产物 Tab。产物卡负责切换，避免用户管理工作视图。
  • 保留
    播放器外壳合同 v1。白壳、20px 圆角、7px 内边距、比例只约束画布。已确认不可回退。
  • 保留
    动作归属唯一化。时间线有重试时，展示区只说明范围，不造第二个按钮。
  • 保留
    建议默认只填输入框。不静默执行，把决定权留给用户。

B · 批注式修改

每个分镜卡常驻一个「说这镜」动作，点它把焦点绑定到该镜并聚焦输入框，用户直接说人话。 修改后明确显示重做范围与复用范围。

核心变化
  • ·
    分镜卡常驻「说这镜」，点击后输入框显示「正在说第 2 镜」并预填可编辑句子
  • ·
    换素材 / 改配音保留为次级，不再是唯一入口
  • ·
    修改完成后展示「已重做 / 已复用」范围条
  • ·
    有上一版本时，标题行常驻「对比 v1」入口
代价
  • +
    直接表达定位第二句，且仍走对话这条唯一路径
  • +
    把增量执行变成用户可见价值
  • +
    不需要新后端能力，范围条可由现有分镜事实推导
  • −
    需要新增「对话焦点绑定某镜」状态，对话与展示区耦合变紧
  • −
    工作量约 A 的两倍

6推荐

推荐方案 B · 批注式修改，分两步落地

  1. 第一步（解除 P0，约 1 周）：分镜卡动作改为常驻；成片页标题行常驻「对比上一版」入口； 修改完成文案补上重做与复用范围。这一步不新增状态机，风险低，立刻解决「核心能力看不见」。
  2. 第二步（表达定位，约 1–2 周）：加入「说这镜」与对话焦点绑定： 点某镜后输入框显示「正在说第 2 镜」并预填一句可编辑的话，发送后焦点自动解除。 配合「已重做 / 已复用」范围条，把增量执行变成用户看得见的省力感。
为什么不选 A：A 只是把按钮露出来，用户仍要自己想到该说什么。定位的差异化不在「有修改按钮」， 而在「可以像对人说话一样改」，这需要焦点绑定才成立。
为什么不选 C：C 的体验诱惑力最大，但它把对话降级，与「对话式 AI 短视频创作工作台」这个已确认品类相冲， 还会让需求理解和编导确认阶段无处安放，并推翻已确认的 V3 骨架、播放器合同检查和截图基线。首发阶段不值得。

本页为只读审查产出，未修改任何产品代码。若确认按 B 推进，下一步先把设计写入 MultiMix-Frontend/docs/plans/active/2026-10-11-segment-annotation-editing.md， 登记开发占用，再改代码；涉及展示区与播放器相关文件时需跑 check:video-preview-contract、test:product-stage-style 与隔离的 test:display-coverage。
