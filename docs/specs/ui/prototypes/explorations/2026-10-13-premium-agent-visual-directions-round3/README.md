# 第三轮视觉方向：I–L（2026-10-13）

不受现有契约约束的一轮。白播放器外壳、对话区宽度、渠道合规这些前两轮的硬约束在这里全部放开，四个方向各自挑战一条原来认为不能动的东西。

**这不是落地候选**，是用来回答「如果那条约束不存在，界面会变成什么样」。每个方向的「代价」一栏写的是真实工程成本。

## 怎么看

打开 `index.html`：四个方向的实时预览、强项/弱点/代价，往下是横向对比表和三个决策点。

| 文件 | 方向 | 打破了什么 |
| --- | --- | --- |
| `screens/i-node-canvas.html` | 血缘画布 | 成片不再是唯一主角，降格为节点 |
| `screens/j-immersive-cinema.html` | 沉浸放映 | 面板和边框全部取消，UI 浮在成片上 |
| `screens/k-console.html` | 调音台 | 浏览态直接给专业控件（推子、电平、走带） |
| `screens/l-gallery.html` | 展陈 | 播放器外壳改成美术馆铭牌 |

内容和前两轮一致（同一条 32 秒隔音视频、同样 5 个分镜），便于直接对比。

## 几个判断

J 和 L 是一对反向答案：同样想让产物显贵，J 用光，L 用留白。J 适合看成品，L 适合审稿，可以是同一产物的两个视图。

I 和 K 都在暴露内部结构，但 I 暴露空间关系（什么来自哪里），K 暴露时间关系（哪镜多长）。两个问题都真实，不必用同一种控件。

最省的组合是 L 的铭牌加 K 的推子：铭牌管来源和形制，推子管时长，不需要画布引擎，也不破坏浅色底。

## 需要确认

1. 要不要深色——I/J/K 深色，L 浅色；深色让成片显贵但要维护两套视觉
2. 来源标注往哪个方向做——I 做成连线，K 做成指示灯，L 做成铭牌印记
3. 节奏信息要不要进浏览态——只有 K 把时长做成了可读的视觉量

## 范围与状态

同前两轮：只画了桌面 1440×900 的视频工作台，未覆盖起始页、资源库、编辑器全屏态和移动端。探索阶段，不影响 `prototypes/current/` 的验收基准。
