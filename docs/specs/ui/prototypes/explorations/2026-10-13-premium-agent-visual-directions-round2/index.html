第二轮视觉方向：E–H

第一轮的 A/B/D 其实是同一个两栏骨架在换配色，所以看起来容易重复。这一轮换的是结构——产物以什么形态存在、修改从哪里发起。方案 C 按你的要求保留，放在最前面作为对照基准。

和第一轮的关系：C 保留为基准，A/B/D 不再推进（第一轮存档）。E–H 都沿用 C 已经验证的两个判断：成片要有重量感、分镜在浏览态就能点能说。四个新方向的差别在于「主产物长什么样」。

1保留的基准

不变，供对照。

方案 C · 保留

Canvas First · 成片优先

成片和分镜卡占左侧主区，对话收成右侧 30% 工作轨。产物是「一条片子 + 一组分镜卡」。

打开全屏 ↗

2四个新方向

每个都是可点开的完整页面，内容完全相同（同一条 32 秒隔音视频、同样 5 个分镜），只有结构不同。

方向 E · 新

Timeline Native · 时间轴原生

把时间轴提成贯穿底部的主脊，四条轨道按时长比例铺开：画面、配音、字卡、配乐。公开素材在轨上是斜纹块，一眼能看出哪段不是你自己的。上方是对话加监看，点任一片段，监看下方的属性条就跟着换。

打开全屏 ↗

强项

  • 专业工具辨识度最高，一眼就是视频软件而不是文档工具
  • 时长比例、配音与画面的对齐关系可见，这是分镜卡做不到的
  • 配乐这种贯穿整条的元素，只有轨道能表达清楚
  • 公开素材的斜纹块在轨上无法忽略

风险

  • 时间轴是「编辑器」的语汇，可能把不懂剪辑的商家挡在外面
  • 和编辑器全屏态职责重叠，需要重新划分谁管什么
  • 底部固定占 196px，监看区被压缩
  • 轨道配色引入 4 种新语义色，和品牌渐变并存需要克制

改造量

  • 需要新建多轨时间轴组件，含缩放与横向滚动
  • 浏览态与编辑态的边界要重新定义
  • 较大：新增最复杂的一个组件
方向 F · 新

Storyboard Deck · 分镜牌组

取消大播放器——成片压成顶部一条摘要带（小封面、播放全片、时长比例条），分镜牌本身成为主产物。每张牌是一镜，自带台词、素材出处、时长和三个动作。牌可拖动换顺序，点「播放全片」才浮层播放。

打开全屏 ↗

强项

  • 修改成本最低：每张牌上就有「说这镜 / 换素材 / 改台词」
  • 换顺序这种高频操作变成拖牌，不需要进编辑器
  • 牌组能自然扩展到多图笔记、多条草稿等非视频产物
  • 最接近商家对「一条内容」的朴素理解：几个片段拼起来

风险

  • 没有常驻大播放器，成片的重量感反而弱于 C，与第一轮 P0 相悖
  • 白播放器外壳契约在浏览态无处落地，需要确认是否改契约
  • 5 镜以上要滚动，整条片子的节奏感不如时间轴直观

改造量

  • 复用 C 的分镜卡，加顶部摘要带和播放浮层
  • 需要拖拽排序与键盘可达的等价操作
  • 中等偏小
方向 G · 新

Script Manuscript · 剧本稿

产物按拍摄脚本呈现：稿纸居中，每一场有场号、时间码、素材出处和衬线正文的配音台词，字卡作为缩进注释。成片退成左侧页边的小播放器，跟着滚动。改脚本里的一句，成片就改对应一镜。

打开全屏 ↗

强项

  • 唯一能让长文案和视频脚本共用一种产物格式的方向
  • 台词是商家真正会逐字修改的东西，这里它是正文而不是卡片附属信息
  • 排版本身就提供高级感，完全不依赖渐变或深色
  • 可直接导出文字稿，对需要先审稿的商家友好

风险

  • 视频感最弱，和「不像视频工具」这条原始批评方向相反
  • 画面只有 26px 缩略图，换素材这类视觉决策缺少依据
  • 衬线中文字体可得性需实测，Windows 上回退可能很难看
  • 朱红印章色是第三套强调色，与现有渐变并存要定规矩

改造量

  • 需要一套文稿排版规范与场块组件
  • 和文案工作台可以共用，长期能省一套组件
  • 中等
方向 H · 新

Viewfinder · 取景框

用真实手机框还原顾客在小红书里刷到它的样子：状态栏、顶部标签、右侧点赞收藏、底部作者与正文标签一并呈现。字幕位置按避开右侧按钮区来排。右边是时间码分镜栏，顶部可切「成片预览 / 封面与文案」。

打开全屏 ↗

强项

  • 所见即所得做到位：字幕会不会被按钮挡住，当场能看出来
  • 把「发布后长什么样」变成默认视图，这是竞品普遍缺的
  • 封面与文案和视频在同一屏，发布前的完整检查闭环
  • 深色手机框天然给成片最高对比，不必让整个界面变暗

风险

  • 手机壳取代了白播放器外壳，直接违反现有视觉契约
  • 模仿第三方平台 UI 有合规与维护风险，对方改版就要跟
  • 手机框占掉大量宽度，分镜栏被压到 206px
  • 只适合单一发布渠道；多渠道时要么做多套框，要么失效

改造量

  • 需要设备框组件与各渠道安全区规则
  • 白播放器外壳契约需明确改写或增加例外
  • 中等，但合规问题要先问清楚

4怎么看这四个

它们不完全互斥，有两组可以叠。

可以叠的组合：C + H 最自然——C 的布局骨架不变，只把中间的白播放器换成取景框，就同时拿到成片重量感和所见即所得。C + F 也成立：F 的牌组本来就是 C 分镜卡的加强版，差别只在要不要保留常驻大播放器。
互斥的：E 和 G 是两个相反极端（时间轴 vs 文稿），选一个就基本排除另一个。E 还会和编辑器全屏态抢职责，需要先想清楚浏览态要做到多深。

5需要你决定

不选完不动代码。

四个决策点

  1. 主产物是什么形态一条片子（C/H）、一组牌（F）、一条时间轴（E），还是一份脚本（G）？这是四个方向的根本分歧。
  2. 浏览态要做到多深E 把时间轴放进浏览态后，编辑器全屏态还剩什么职责？需要你划线。
  3. 白播放器外壳契约是否可改F 让它无处落地，H 用手机壳取代它。两个都需要你批准改契约。
  4. 要不要模仿小红书界面H 的核心价值来自这个，但有合规和跟版维护成本。这个要你拍。
