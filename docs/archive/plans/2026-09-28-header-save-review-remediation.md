## 背景与根因

用户确认修复最新审查的两个问题，不包含独立剪辑器素材替换。

- P1：`app/assets/components/product-workspace.tsx:1919` 的通用保存调用资产正文 PATCH，不保存内嵌编辑器的时间线。故障复现：分割后时间线 PUT 返回 503，资产 PATCH 仍返回 200，界面同时显示“已保存”和“重试保存”，服务端仍是三段、本地四段。
- P2：`app/assets/lib/asset-workspace-adapter.ts:1418` 丢弃 PATCH 响应并猜测当前版本加一。后端重复保存去重，因此实际 v1 被显示为 v2。
- 后端 `app/api/assets.py:update_asset / _append_version` 已返回资产真实版本并对相同内容去重；不改变后端契约。

## 具体设计与边界

1. 视频编辑态隐藏通用资产保存按钮。既有“完成编辑 / 正在保存… / 重试保存”是唯一手动保存与退出入口，继续复用时间线 flush、配乐写入队列、版本及内容代次保护。浏览态普通保存保留，图片与文本编辑流程不变。
2. adapter 使用 PATCH 返回的 `versions[].version` 最大合法正整数作为保存反馈，不按数组长度或客户端旧版本猜测。缺失或非法版本响应不返回伪成功；保存时间使用服务端 `updated_at`。
3. 不新增第二套保存状态，不修改播放器外壳、时间线结构、导出或独立编辑器。不用完整资产响应覆盖可能正在编辑的新产品状态。

涉及实现与测试：上述两份实现文件，`app/assets/__tests__/asset-workspace-adapter.test.ts`、`app/assets/__tests__/product-workspace-video-actions.test.tsx`；说明补充 `docs/API.md`。

## 风险与取舍

- 编辑时不能点击普通资产 PATCH；用户仍可依靠自动保存或“完成编辑”手动保存，无需新增重复入口。
- 响应缺少合法版本时可能已写入，但客户端无法核验，不能显示成功版本；现有错误提示及刷新后核对保留。
- 浏览态资产版本与时间线保存是不同职责；本轮不扩展为新版本体系，不修改后台数据或生产配置。
