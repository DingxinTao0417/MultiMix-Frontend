# 视频版本对比独立模式

> Status: archived
> Owner: frontend
> Last verified: 2026-09-26

## 背景与根因

当前视频工程浏览态在 `app/assets/components/product-preview.tsx` 约 493 行以后固定渲染一份播放器和完整分镜列表；历史版本只在 `app/assets/components/product-workspace.tsx` 约 1482 行的详情浮层中提供正文预览与恢复。若直接在当前浏览态下追加双播放器和修改分镜卡，就会同时出现“受影响分镜”和“全部分镜”两批结构相似的卡片，既重复占用空间，也混淆“继续制作”和“验收版本”的职责。

本轮已确认的产品边界：

- 单视频模式负责浏览和制作：显示当前稳定版本、全部分镜和现有换素材/修改配音入口。
- 版本对比模式负责验收：显示上一稳定版本与当前稳定版本两个完整视频，只显示受影响分镜的差异导航，不显示完整分镜列表、来源块或制作型操作。
- 点击差异导航时，两边完整视频分别跳到该分镜在各自版本中的真实起始时间并同步播放；不把主播放器替换为孤立分镜素材。
- 当前版本仍以服务端已经原子发布的稳定版本为准。本轮不伪造“待采用版本”状态；恢复旧版继续使用现有追加式版本恢复入口。

## 涉及文件与关键位置

- `app/assets/components/product-workspace.tsx`：约 205、400、1853 行；读取上一版本安全快照、管理对比加载/失败/自动打开状态并传给视频预览。
- `app/assets/components/product-preview.tsx`：约 239、285、493 行；增加单视频/版本对比模式，双播放器和受影响分镜导航。
- `app/assets/lib/video-version-comparison.ts`：新增确定性的分镜版本差异投影，不做关键词或语义猜测。
- `app/globals.css`：在现有视频浏览态样式之后增加模式切换、双播放器和紧凑差异导航；不修改 `.shadcn-prototype-preview-player*` 的白色外壳、比例、圆角、内边距、控件或阴影合同。
- `app/assets/__tests__/video-version-comparison.test.ts`：验证新增/删除、时长、画面、口播/字幕与 MG 的结构差异投影。
- `app/assets/__tests__/product-workspace-video-actions.test.tsx`：验证历史版本加载、两种模式分离、对比模式不重复完整分镜卡，以及点击差异后双视频跳转。
- `docs/specs/ui/video-artifact-browse-and-edit-states.md`：补充版本对比浏览态合同和验收案例。
- `docs/MULTIMIX_WORKSPACE_DESIGN.md`：补充单视频制作 / 版本对比验收的职责边界。
- `docs/specs/ui/prototypes/current/screens/workspace-video.html`：把已确认的模式切换与不重复分镜视觉更新到当前原型，保留播放器外壳合同。

## 具体改法

1. 复用现有 `GET /assets/{asset_id}/versions/{version_id}/preview`，按当前版本列表读取紧邻的上一稳定版本；用既有 `contentAssetToProduct` 投影为只读历史视频工程，不新增后端接口或第二套版本数据。
2. 只有当前工程已完成、当前成片可播放且至少存在两个版本时显示“版本对比”入口。历史快照没有可播放成片时保留单视频模式并给出明确失败说明，不渲染空双播放器。
3. 冷启动默认保持单视频模式；同一已挂载工作台观察到视频稳定版本从 vN 更新为 vN+1 时，自动读取上一版本并进入对比模式。这样只在本轮修改完成后主动验收，不让旧项目每次打开都强制进入对比。
4. 差异投影按稳定分镜 ID 对齐，缺失 ID 时仅以相同序号兜底；比较起止时间、标题、口播/字幕、素材身份、主画面来源、MG 标识与状态等结构字段。Python/前端不按文案关键词猜测语义。
5. 对比模式渲染两个现有 `VideoPreviewPlayer`，分别使用历史与当前成片 URL，继续复用同一白色播放器外壳。点击差异条后分别设置两边 `currentTime`，在媒体可播放时同步启动。
6. 单视频模式保持现有播放器、全部 `SegmentCards`、素材缺口、来源与审查/记忆 footer；对比模式只渲染双播放器、同步定位状态和紧凑差异条，消除重复卡片。

## 风险与取舍

- 历史版本可能没有保存 MP4 引用。此时不能用当前工程或原始分镜素材冒充上一版成片，只保留单视频并说明无法对比。
- 两条视频由浏览器分别解码，长时间同步播放可能出现轻微漂移。本轮保证点击差异时的起点同步；不引入音频主时钟或逐帧锁步，避免把展示区做成专业剪辑器。
- 分镜重排可能同时改变 ID 和序号。首版坚持确定性 ID / 序号对齐，无法可靠对应时显示新增或移除，不用文本相似度制造伪匹配。
- 当前服务端在修改成功后已将新版本原子发布为稳定版本，因此对比模式不新增“采用 v2”假状态；用户若要回到旧版，继续通过详情中的“基于此版本继续”生成新的当前版本。
- 双播放器仍使用既有媒体代理和权限；不缓存或暴露私有存储引用。

## 验证方式

1. TDD：先补差异投影和工作台交互失败用例，再实现最小行为。
2. 组件测试覆盖：默认单视频、点击进入对比、历史加载失败降级、对比模式仅显示受影响分镜、点击差异同步设置两边时间、返回单视频恢复完整分镜列表。
3. 运行 `npm run check:video-preview-contract`、`npm run test:product-stage-style`、隔离的 `npm run test:display-coverage`，证明播放器外壳和展示区合同未回退。
4. 运行相关 Vitest、`npm run typecheck`、`npm run lint`、`npm run docs:check` 与 `git diff --check`。
5. 使用浏览器在桌面和窄屏 fixture 验证模式切换、双播放器、差异导航、无重复分镜列表、无横向溢出和控制台错误；不连接生产数据库。

## 本轮实施与验证记录

- 已接入当前完成版与上一稳定版的只读双播放器；结构差异按稳定分镜 ID、序号和可展示字段投影。历史分镜结构缺失时不伪造新增分镜，明确提示用户直接观看两条完整视频。
- 已处理版本异步发布和历史快照晚到：新版本待 MP4 就绪后再自动打开；切换到其他视频会丢弃旧请求结果。对比只在点击差异时同步定位，不承诺长时间逐帧同步。
- 相关 Vitest 45 项、展示区组件 40 项、TypeScript、lint、播放器契约、展示区样式合同、文档检查与 `git diff --check` 通过。
- 隔离展示区 E2E 已执行并清理一次性 SQLite：19 项中 14 项通过、4 项失败、1 项跳过。失败点是已有“新对话创作起点”断言、视频库分页数量、两张旧播放器基线图 279px/280px 的环境差异；本轮没有修改基础播放器壳或这些页面，不为通过检查擅改旧基线。
- 当前原型在 1440×900 与 1280×900 浏览器窗口验证：版本对比可切换，点击受影响分镜后两侧时间分别变化，返回单视频可见；无页面横向溢出或脚本错误。当前隔离种子只有单版本 CASE-07，尚无真实双成片数据的端到端播放验收样本，这是后续上线前仍需补齐的风险。
