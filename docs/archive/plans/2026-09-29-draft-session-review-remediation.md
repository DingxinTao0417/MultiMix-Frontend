# 上传晚到与取消编辑会话整改

> Status: archived
> Owner: frontend
> Last verified: 2026-09-29

## 背景与根因

用户批准修复只读复查确认的两处问题：

- P1：资产库上传尚未完成时返回项目编辑，上传回包调用捕获旧库视图的 `setActiveView`，绕过离开确认并卸载编辑器；返回项目后未保存正文丢失。
- P2：同一产物外部更新保留草稿后，确认取消只关闭编辑器，却残留旧编辑基准和冲突状态；浏览区显示新正文，再进入编辑却显示旧正文。

两项均已由真实接口、隔离 SQLite、Chromium 页面复现。后端已保存正文未发生覆盖，不修改后端接口或数据契约。

## 具体改法

1. 先补失败回归：慢上传后切回项目/其他库、普通库上传刷新；冲突后取消并重新编辑，取消确认拒绝/外部更新/新输入边界。
2. 删除上传完成后的页面切换副作用，保留库刷新计数；用户自行决定当前页面，不新增强制弹窗或后台自动保存。
3. 确认放弃后结束旧编辑会话，清除旧基准、冲突、已保存反馈、结构提示及读取标记；正文取当前已知最新已保存内容。若冲突只读已取得更晚正文，回填同一产物供浏览使用，不发 POST。拒绝确认或确认期间上下文/输入变化仍保留草稿；晚到读取不得回填结束后的会话。
4. 跑离线检查和真实接口浏览器回归，清理测试库与进程，记录证据并归档计划。

## 风险与取舍

- 不用“禁止离开资产库直到上传完成”规避问题；从根因移除非用户发起的导航。
- 保留上传完成后的库刷新，回到原库仍可见新资料。
- 取消是用户确认放弃当前草稿，不应等价于确认覆盖服务端正文；仅更新客户端最新快照。
- 不削弱未保存导航、409 冲突对照或保存期间继续输入保护；不改 CSS、播放器、素材理解、模型、费用或生成路由。
- 本轮不提交、不推送、不部署；不使用用户主库。
