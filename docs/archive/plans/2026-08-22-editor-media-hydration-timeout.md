# 工程预览素材加载超时收敛

> Status: archived
> Owner: frontend
> Last verified: 2026-08-24

## 背景与根因

生产工程 `asset-1207` 已完成，但工作台预览持续显示“正在下载素材 1/2”。编辑器初始化会先把全部
媒体下载成 Blob，供画布解码器使用；当其中一个媒体连接没有响应时，当前 300 秒超时会阻塞整个
预览。现有失败分支本可保留原播放 URL 继续初始化，但直到超时才会执行，造成用户看似无限加载。

## 改法

1. 在 `editor-engine/vendor/bootstrap.ts` 将单个媒体的无响应等待上限收敛为 15 秒，并保留命名常量。
   它只限制 Blob 预下载，不限制工程时长或后续 `<video>` 的播放。
2. 超时后继续复用既有降级：保留媒体原 URL，初始化其余媒体并让预览进入可播放状态；现有 HTTP、
   MIME 和网络错误诊断保持不变。
3. 在 `editor-engine/vendor/bootstrap.test.ts` 将挂起请求的回归测试改为验证 15 秒后会完成降级，
   避免再次把长时间挂起当成可接受行为。

## 风险与取舍

- 网络较慢时，素材可能不被预下载为本地 Blob，但仍通过既有后端媒体地址直接播放；用户获得的是
  可用预览而非无限等待。
- 不改变视频工程、导出、素材地址、认证或音画内容。

## 验证

1. 运行 bootstrap 单元测试，验证挂起媒体在 15 秒后降级，其余媒体照常可用。
2. 运行工程预览相关契约测试与类型检查。
3. 发布前端后重新打开生产工程 `asset-1207`，确认播放器不再长期停在“正在下载素材”。

## 实施与验证记录（2026-08-24）

- 当前 `main` 已在 `editor-engine/vendor/bootstrap.ts` 使用命名的
  `MEDIA_HYDRATION_IDLE_TIMEOUT_MS = 15_000`，以 `AbortController` 中止无响应的 Blob 预下载；
  超时后既有失败路径保留原播放 URL，工程其余素材继续初始化。
- `npx vitest run editor-engine/vendor/bootstrap.test.ts` 通过（3 passed），其中挂起媒体用 fake
  timer 在 15 秒时被中止、保留直连 URL，另一个媒体仍成功 hydration。
- 因此本计划不再缺实现或离线回归；仅保留一次生产工程 `asset-1207` 的人工复验。该复验不能由
  单元测试替代，且不应为此重复改动超时逻辑。

## 生产复验记录（2026-08-24）

- 已获用户授权，以只读方式在生产工作台输入该工程编号。素材库的关键词与语义检索均未返回该编号；
  这不构成“素材已删除”的证据，因为这两个检索入口按素材内容而非后台 ID 匹配。
- 随后直接打开既有剪辑器路由 `/editor?asset=1207`，连续等待约 17 秒后，页面已进入编辑器布局、
  创建两个画布，加载壳和错误状态均不存在，并显示仅在 ready 状态才会出现的导出操作。编辑器使用
  画布渲染，因此没有 HTML `<video>` 元素不是失败信号。
- 结论：生产人工复验通过，挂起媒体不会把该工程长期停在“正在下载素材”。无需再修改超时逻辑。

## 归档结论（2026-08-24）

- 当前主线实现、3 项离线回归与生产只读复验均完成。本计划不再保留待办，归档以避免把已验证的
  timeout 修复误当成需要重做的缺陷。
