# Agent 工作台视觉升级

> Status: completed
> Owner: frontend
> Last verified: 2026-09-23

## 背景与根因

当前工作台已经具备项目导航、对话、确认、真实任务进度、产物切换、视频预览和分镜摘要，但这些可见模块更像独立的功能消息。用户确认以“编导协作过程”为视觉方向：让用户一眼分辨创作目标、AI 的判断、当前确认、真实执行状态和当前视频结果。

本轮只做视觉与信息层级升级，不将概念图中的百分比、预计剩余时间或额外 Agent 阶段硬编码到产品中。所有状态继续消费现有后端返回；播放器已确认的视觉合同保持不变。

## 涉及文件与关键位置

- `app/assets/components/assets-workspace-client.tsx`：现有工作台壳、左侧导航和桌面布局的展示接线；只在需要补充无行为风险的展示标识时修改。
- `app/assets/components/conversation-studio.tsx`：用户/助手消息、建议、产物卡和输入框的视觉语义。
- `app/assets/components/confirm-card.tsx`：现有真实确认字段、主要确认与调整动作的摘要层级。
- `app/assets/components/video-progress-card.tsx`：真实视频任务步骤的呈现密度和进行中状态。
- `app/assets/components/product-workspace.tsx`：右侧产物头部与分镜摘要周边的视觉容器；不改播放器行为。
- `app/globals.css`：工作台三栏、左侧导航、对话、确认、进度、输入框和展示区的视觉 token 与响应式样式。
- `docs/MULTIMIX_WORKSPACE_DESIGN.md`、`docs/specs/ui/prototypes/current/screens/workspace-video.html`、`docs/specs/ui/prototypes/current/screens/workspace-copy.html`：同步已确认的视觉层级与当前原型。
- 对应前端组件/静态/截图测试：保持既有真实状态、视频预览合同与关键交互不回归。

## 具体改法

1. 保持现有“三栏导航 / 对话 / 当前产物”结构、桌面宽度边界和拖拽分隔条。左侧最近项目保持主任务，四类资源库仍为 `2 × 2` 轻量卡片；只提升缩略图、选中态、图标底座和文本层级，不改导航与数据分类。
2. 将对话视觉整理为清晰的创作回合：用户消息保持轻量；助手消息用固定的“AI 编导”展示身份与正文层级；产物卡、确认卡、建议动作和进度卡按同一回合对齐。不得改变消息顺序、路由、建议点击语义或确认门。
3. 将现有确认卡收敛为“当前方案摘要 + 明确主动作 + 次级调整”。默认突出已有主题/时长/比例/配音等服务端字段；复杂选择继续按当前控件、确认 ID 与费用规则工作，不在前端伪造目标人群、制作费用或素材结论。
4. 优化视频任务卡的状态感：进行中时清楚展示真实已完成、当前和待执行步骤；完成后仍按既有规则收起。没有服务端可靠数据时不显示进度百分比、剩余时间或虚构步骤。
5. 将输入框改为更克制的创作指令台：保留图片、视频、文档三个独立上传入口、上传状态、停止按钮、IME 提交和错误提示；降低渐变描边和阴影的视觉权重，强化当前产物的自然语言修改提示。
6. 提升右侧视频工程的标题、状态、分镜摘要和当前选中分镜的层级；只调整播放器外部信息与间距。继续遵守 `video-preview-shell-contract:v1`：白色外壳、边框、圆角、内边距、阴影、媒体比例、播放控件和自然占高均不改变。
7. 更新权威设计和当前原型，补齐组件与静态契约测试；桌面、窄屏、超长对话、待确认、生成中、失败重试和已完成视频均使用真实状态验证。

## 风险与取舍

- 视觉图中的数字进度、预计时间和阶段名称只有在服务端明确提供时才可显示；本轮宁可少展示也不伪造 Agent 正在做什么。
- 助手身份、时间与缩略图只能使用现有消息、产物或真实媒体字段；字段缺失时以稳定的文本/图标降级，不能引入 mock。
- 对话区和右侧展示区都可能超高，继续各自独立滚动；不为追求概念图静态效果破坏长内容可达性。
- 不修改受保护播放器合同，避免将“更简洁”误解为移除白色播放器外壳。
- 该分支从隔离 worktree 创建，不包含主工作目录已有未提交改动；合并前必须基于最新 `main` 处理同文件差异并复测。

## 验证方式

- 单元/组件：消息建议填入输入框、确认卡字段与确认语义、视频任务的完成/失败/重试状态、附件上传与 IME 提交保持不变。
- 静态/样式：三栏宽度、桌面独立滚动、卡片层级、窄屏和无数据/失败降级。
- 受保护视频链路：`npm run check:video-preview-contract`、`npm run test:product-stage-style`、`npm run test:display-coverage`。
- 前端质量：`npm run typecheck`、`npm run lint`、相关 Vitest、`npm run docs:check`、`npm run build`。
- 浏览器验收：用真实或现有受控 fixture 覆盖长对话、待确认、生成中、任务失败和视频完成展示；不连接生产数据库或创建持久本地数据库。

## 实施结果（2026-09-23）

- 已完成三栏工作台、项目/资源导航、对话回合、确认/进度、输入框和右侧工程信息的视觉层级升级；保留现有路由、确认门、上传、IME、停止和错误恢复交互。
- 已同步当前视频与文案原型、工作台设计规则，以及浏览器截图基线；受保护播放器保持既有视觉合同。
- 已通过类型、lint、相关 Vitest、文档、播放器合同、产品展示样式和 production build 验证。
- 展示区 E2E 真实运行后有两个既有链路未通过：CASE-07 下载事件等待超时、视频库分页数量为 62 而预期 65。两项均不由本轮视觉改动引起；隔离 SQLite 与临时素材目录已清理。
