# 极窄屏对话标题可读性修复

> Status: archived
> Owner: frontend
> Last verified: 2026-09-30

## 背景与根因

上轮裁切修复已让资料、诊断和发送按钮完整进入 320px 视口，但 320px 真实截图中项目标题几乎只剩首字母。`app/assets/components/conversation-studio.tsx:1208-1227` 把导航、标题和操作区放在同一行；`app/globals.css:3174-3203` 让操作区保持不可收缩，剩余标题宽度接近零。这会削弱当前项目的识别感，不属于继续缩小字体可以解决的问题。

## 涉及文件与关键位置

- `app/globals.css:3174-3203,12030-12042`：仅在极窄屏重排已有项目对话头部；保持上轮可收缩网格、播放器样式不变。
- `e2e/display-area.spec.ts:53-121`：扩展既有真实浏览器回归，验证标题可读宽度、操作区位置与控件边界。
- `docs/MULTIMIX_WORKSPACE_DESIGN.md:76,210-212,229`：补充极窄屏头部的两行布局约束，仍保持对话标题和资料入口同一头部而不新增独立横条。

## 具体改法

先为 320px 标题添加至少 120px 可用宽度及操作区位于标题下方的断言，取得修复前失败。然后在 `max-width: 380px` 的响应式规则中，把头部排成两行：第一行侧栏展开入口 + 可省略的项目标题，第二行右对齐原有资料/诊断操作区。没有操作区时自然只保留首行。390px 及桌面仍维持单行；不隐藏功能、不降低字号、不改变按钮顺序。最后同步当前 UI 规范。

## 风险与取舍

极窄屏头部会增加约一行高度，换取项目名可辨识；必须确认对话卡与输入区仍可正常滚动/操作。开发/管理员可见诊断的状态作为最拥挤情况，普通账号因无诊断只会更宽松。现有前端未提交改动属于上一轮修复，不覆盖、不提交。生产保存接口、真实资料抽屉完整验收与发布均不在范围内。
