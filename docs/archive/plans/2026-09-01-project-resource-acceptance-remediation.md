# 项目资源验收问题整改计划

> Status: current
> Owner: frontend
> Last verified: 2026-09-01

## 背景与根因

项目化体验首轮产品验收确认了两个 Major（P1）问题：

1. `app/assets/components/conversation-studio.tsx` 的对话卡片会依次渲染标题、项目资源、可选 Agent 任务状态、消息区和输入区，但 `app/globals.css` 的 `.shadcn-prototype-chat` 仍只有三行网格。新增的顶部区块因此可能占用消息区的弹性高度，并在较小视口遮挡点击。
2. `app/assets/components/assets-workspace-client.tsx` 的项目资源抽屉中，“添加素材”把 `activeView` 设置为 `image`，导致用户进入图片库，而不是包含图片、视频、音频和文档的资产库。项目目标本身能保留，错误只在入口目的地。

## 涉及文件与具体改法

- `app/assets/components/conversation-studio.tsx`（当前约 895–927 行）
  - 将标题、项目资源和可选 Agent 任务状态收进同一个顶部上下文容器。
  - 保持对话卡片的三段结构：顶部上下文、可滚动消息区、输入区，避免用固定四行或五行规则绑定可选模块数量。
- `app/globals.css`（当前约 1421、2819、2997 行）
  - 为顶部上下文容器增加只按内容自然占高的布局约束。
  - 保留项目资源条现有 30px 最小高度、分隔线和视觉样式。
- `app/assets/components/assets-workspace-client.tsx`（当前约 2991–2997 行）
  - “添加素材”改为进入 `assets` 资产库；继续保留目标项目标识和返回项目能力。
- `app/assets/__tests__/conversation-project-resources.test.tsx`
  - 增加结构回归：无论顶部可选区块是否出现，对话卡片都只有顶部上下文、消息区、输入区三个直接子区块。
- `app/assets/__tests__/project-resource-entry-contract.test.ts`
  - 增加入口回归：项目资源抽屉的“添加素材”必须进入资产库，不能退回图片库。

## 风险与取舍

- 不增加新的导航或资产分类，只修正现有入口目的地，避免扩大产品范围。
- 不用固定网格行数逐项适配可选模块；顶部统一容器能兼容项目资源为空、Agent 状态出现或消失等状态。
- 不调整对话区、素材库和项目资源抽屉的接口或数据结构，后端无改动。
- 本次不处理离线模型输出质量；该项在首次验收中属于待生产环境验证风险，不是这两个 P1 的根因。

## 验证方式

- TDD：先运行新增定向测试并确认在旧实现上失败，再做最小修复并确认转绿。
- 自动检查：定向 Vitest、完整 Vitest、构建、文档检查、Agent 规则检查、播放器契约检查和产品展示区样式检查。
- 浏览器复测（隔离本地后端和一次性 SQLite）：
  - 1440×960：项目资源条自然占高，消息区和输入区位置正常。
  - 1280×720：项目资源条可真实点击并打开抽屉，不被消息区遮挡。
  - 点击“添加素材”直接进入资产库，并显示当前目标项目。
- 通过标准：两个 P1 均不可复现，浏览器无新增控制台错误，相关自动检查全部通过。
