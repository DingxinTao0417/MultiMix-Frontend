# 项目资料入口与资源面板轻量化

> Status: archived
> Owner: frontend
> Last verified: 2026-09-23

## 背景与根因

已有项目资源时，“本项目资料”仍占据聊天标题下的一整行；点击后抽屉把分类总数、当前/历史使用统计和多个边框按钮并列展示，即使分类为空也保留入口。它把辅助性的项目上下文管理做成了后台统计页，挤压首屏对话空间，也难以突出用户真正关心的资料列表、当前可用状态和移出动作。

本次不改变项目资源的归属、历史引用、恢复和永久删除契约，仅优化已有资源时的入口位置与抽屉信息层级。

## 涉及文件与关键位置

- `app/assets/components/conversation-studio.tsx`：把资源入口放入聊天标题右侧；保留空项目不显示的规则。
- `app/assets/components/project-resources-drawer.tsx`：只显示有内容的分类；将来源筛选收敛为简洁状态切换，重组列表状态和操作层级。
- `app/globals.css`：入口按钮、窄侧栏、资源缩略块、空态和移动端视觉。
- 相关组件测试与 `docs/MULTIMIX_WORKSPACE_DESIGN.md`、`workspace-copy.html`：同步可见行为与契约。

## 具体改法

1. 标题左侧保留项目名称；右侧在有资源时显示紧凑的文件夹图标与“资料 · 数量”，不再增加标题下方的独立横条，也不展示细分类计数。
2. 将抽屉标题调整为“本项目资料（总数）”，说明这些资料会用于后续对话与生成；仅渲染有内容的资料类型。来源分类默认显示“可用于后续生成”，历史引用改为低优先级的“已移出”查看入口。
3. 资源列表使用类型视觉块（图片、视频、文档）和名称/可用状态；主操作是查看和移出项目。“用于本轮”保留为次级动作，永久删除继续保留在二级危险操作。
4. 空分类改为轻量空态，不显示零统计；抽屉不提供上传入口，上传仍在聊天输入框完成。

## 风险与取舍

- 隐藏空分类降低了发现性，但避免零计数噪音；分类在加入第一项资源后自动出现。
- 抽屉默认只加载当前可用来源，历史资料仍可查、可恢复，不能被视觉收纳误解为删除。
- 不修改接口、分页、资源归属或历史引用的后端定义。

## 验证方式

- 组件测试：空项目无标题入口；有资源时标题右侧有紧凑入口；抽屉不显示零分类，来源和历史资料仍可管理。
- 运行相关 Vitest、`npm run lint`、`npm run typecheck` 与 `npm run docs:check`。
- 如本地 UI 环境可用，检查桌面与窄屏抽屉的标题对齐、列表可读性和键盘关闭行为。
