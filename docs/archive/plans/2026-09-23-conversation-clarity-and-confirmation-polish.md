# 对话资源、确认卡与视觉清晰度收敛

> Status: archived
> Owner: frontend
> Last verified: 2026-09-23

## 背景与根因

新项目没有任何资源时，聊天标题下仍显示“项目资源 0”，并可打开带有分类、计数和“添加素材”的抽屉。这把项目长期资源管理误呈现为首次对话的必经入口，也与聊天附件承担“带入本轮素材”的实际入口重复。

右侧产物失败时，旧的编导时间轴只检查“未生成工程且有 timeline”，没有排除失败状态，因而会把未成功落地的计划误显示成当前结果。

新建页的“可组合能力”把素材来源、画面制作方式和后期能力平铺为六个同级标签。现有工作台在全局和工作台区域使用不同字体栈，并广泛使用偏小字号和非标准字重，中文、英文和数字的视觉节奏不稳定。视频方案确认卡的跨端展示投影另见 `MultiMix-Backend/docs/plans/active/2026-09-23-video-confirmation-card-clarity.md`。

## 涉及文件与关键位置

- `app/assets/components/conversation-studio.tsx`：只在项目已有资源时显示资源管理入口。
- `app/assets/components/project-resources-drawer.tsx`、`app/assets/components/assets-workspace-client.tsx`：将抽屉定位为已有项目资源的管理，不再提供与聊天附件重复的新增素材入口。
- `app/assets/components/conversation-start.tsx`：将新建页制作能力收敛为用户可理解的五类组合方式。
- `app/assets/components/product-workspace.tsx`：失败态不渲染编导时间轴；稳定成片局部操作失败继续由已有稳定版本路径表达。
- `app/globals.css`、`app/layout.tsx`：统一工作台字体入口、字号/字重/对比度 token，并调整上述组件的视觉层级。
- `app/assets/__tests__/conversation-project-resources.test.tsx` 及相关展示区测试：覆盖空资源隐藏、失败态不展示时间轴和能力标签。
- `docs/MULTIMIX_WORKSPACE_DESIGN.md`、`docs/specs/ui/prototypes/current/screens/workspace-*.html`：同步当前的项目资源入口、能力提示与字体说明。

## 具体改法

1. 将“项目资源”明确为跨消息、跨产物的长期归属与移出/恢复管理；聊天消息继续展示刚上传的素材、理解结果和当前采用理由。资源总数为零时不渲染入口；有资源时显示紧凑的“本项目资料”入口。抽屉保留已有资源的查看、移出、恢复和删除，不再作为上传入口。
2. 将新建页被动能力提示改为五个明确能力组：我的素材、AI 画面与镜头、公开素材、字幕/图文/图形动画、原片优化/配音与音乐。它们只说明可以混合采用的方式，不构成用户必须选择的技术菜单。
3. 在右侧预览时间轴的渲染条件中纳入产品失败状态。首次生成失败时仅显示失败原因和恢复动作；已有稳定版本的局部操作失败维持既有稳定版本与单独失败提示，不把失败尝试的时间轴作为当前结果。
4. 使用单一、实际可用的中英文字体栈作为工作台入口；收敛正文、元信息、标题的字号与行高，使用 400/500/600 字重并提高正文/次要文本对比度。抽屉遮罩继续只服务于打开态，不将遮罩导致的背景变暗视为字体问题。
5. 同步权威设计与当前原型，补齐组件测试和静态样式断言；不修改后端资源归属、失败恢复或付费动作契约。

## 风险与取舍

- 隐藏空资源入口会减少首次上传的显式入口，但聊天输入框附件仍是唯一清晰的“带入素材”动作；用户已有资源后仍可管理项目上下文。
- 字体视觉效果受操作系统安装字体影响。本次优先消除同页的字体栈冲突和合成字重，不引入未经许可的远程字体加载。

## 验证方式

- 组件测试：空项目没有“项目资源”按钮；有资源时显示紧凑入口；资源抽屉不再提供重复上传入口。
- 展示区测试：失败产品不渲染“时间轴预览”；已完成产品的既有时间轴不回归。
- 静态/样式测试：新建页五类能力提示、统一字体栈与标准字重生效。
- 运行相关 Vitest、`npm run lint`、`npm run typecheck`、`npm run docs:check`；如本地环境可用，运行现有工作台浏览器截图/E2E，检查桌面和窄屏排版。
