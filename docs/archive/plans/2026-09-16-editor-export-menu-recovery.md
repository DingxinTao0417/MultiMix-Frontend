# 生产编辑器导出菜单遮挡与旧中断提示修复

> Status: archived
> Owner: frontend
> Last verified: 2026-09-17

## 背景与根因

生产工程 1524 在后端 `fitMode` 修复后已由生产编辑器导出为 1080×1920、15 秒 MP4，质量任务通过，四幕内容完整。实际鼠标操作却无法选择“原始成片”：`app/editor/editor.css:291` 的 `.editor-actionbar` 使用 `backdrop-filter` 形成层叠上下文，后续 `.editor-layout` 的预览画布覆盖下拉项；`app/globals.css:2662` 仅提高菜单在该上下文内部的 `z-index` 无效。键盘 Enter 可完成导出，说明导出服务本身可用。

另一个竞态在 `app/editor/EditorView.tsx:765-840`：页面就绪时异步查询现有导出任务，用户在查询返回 404 前启动新导出并写入本地标记；查询返回后把这个新标记当作“上次导出中断”，显示错误。真实导出期间和完成后都可能留下假错误文案。

## 涉及文件与具体改法

1. `app/editor/editor.css`：让 `.editor-actionbar` 成为位于 `.editor-layout` 之上的定位层，保持现有背景、尺寸和菜单样式；不改视频预览播放器契约。
2. `app/editor/EditorView.tsx`：在异步查询开始前记录既有的本地导出标记，只对查询前已存在且查询后仍相同的标记提示“上次中断”；新导出写入的标记不触发旧错误。
3. 使用隔离端口的 Playwright QA 脚本：以真实鼠标命中验证菜单项可点击；让现有任务查询在新导出开始后才返回 404，检查不再误报。只运行与该行为相关的测试、类型和文档检查。
4. `MultiMix-Backend/docs/qa/production-feature-flag-convergence-2026-09-16.md`：记录生产 MP4 与这两个剩余 UI 问题。前端部署仍需本轮明确授权，未部署前不宣称鼠标导出体验已修复。

## 风险与取舍

- 顶部操作栏提高层级可能与其它编辑器弹层相交；浏览器验证打开菜单后鼠标命中、关闭菜单及预览控件。
- 中断提示只依据进入页面前的持久标记，仍保留真正中断后的恢复提示；避免以删除提示替代竞态修复。
- 产品当前以 `contain` 保留横屏 MG 全部内容，竖屏成片有明显上下黑边；这是素材比例适配限制，需要在验收结论中明确呈现。

## 验证方式

- 先复现：生产编辑器 Playwright 鼠标点击菜单项被预览画布拦截；延迟任务查询后启动导出出现假“上次中断”提示。
- 修复后通过隔离端口的本地前端和验收账号验证鼠标点击，以及延迟查询期间没有旧错误；不对真实用户账号操作。
- 运行相关前端测试、`typecheck`、`docs:check`。最终生产效果在获得前端部署授权后复测。
