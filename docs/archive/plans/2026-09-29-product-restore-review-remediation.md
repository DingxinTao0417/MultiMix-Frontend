# 历史版本恢复并发与冲突恢复整改

> Status: current
> Owner: frontend
> Last verified: 2026-09-29

## 背景与根因

用户批准整改本轮只读审查发现的问题：两个历史恢复可同时发起，较早请求晚到会将服务器 v5 的界面回退到 v4。恢复期间仅当前版本按钮禁用，恢复回包直接替换产物，没有普通保存已有的基准和认证保护。另批准增加保存冲突后的显式读取入口，保留未发送输入，不自动重新保存。

## 涉及文件与关键位置

- `app/assets/components/assets-workspace-client.tsx:782` 操作状态、`:1861` 共享协调器、`:1918` 保存、`:1923` 读取、`:1931` 恢复、`:3481` 受控状态。
- `app/assets/components/product-workspace.tsx:214` 恢复状态、`:1767` 历史按钮、`:1852` 文本编辑、`:1899` 视频编辑、`:1942` 保存、`:1952` 提示区。
- `app/assets/lib/product-save-state.ts` 互斥与基准回填；对应 `product-save-state.test.ts`、`product-workspace-video-actions.test.tsx`。
- `docs/API.md` 保存、历史恢复和刷新交互契约。
- 后端只验证现有保存和历史恢复接口，不改 schema、数据、恢复服务或语义路由。播放器、vendor、全屏独立剪辑器、生产配置不在范围内。

## 具体改法

1. 普通保存、历史恢复和冲突读取共用同一产物的同步互斥，避免跨操作重复请求。回填共用资产身份、会话和请求基准时间校验；认证作用域及卸载后请求失效。失败释放占用。恢复返回后同步标题、产物卡、历史与保存反馈；不依据本地猜测增加版本。
2. 历史恢复中禁用全部恢复、保存和进入编辑；已进入文本/视频编辑时禁用历史恢复。读预览仍允许。冲突读取期间同样禁用写入入口；相关浏览态素材/配音入口暂停，保留当前画面和播放。
3. 保存 409 除通知外显示绑定当前基准的持久提示和“读取最新版本”。点击后只 GET 当前项目并回填对应产物，不刷新整页、不清理输入、不 POST 保存。读取失败继续保留原产物/输入及重试入口。过期或其他账号响应不回填，后续产物更新自动使旧冲突提示失效。
4. 窄屏实际点击发现：独立插入提示会占用产物网格的伸缩行并被图片遮挡。提示与原头部共用一个自然高度网格项，保留主预览行及所有播放器样式；补 DOM 几何不重叠及窄屏真实点击验证。

## 风险与取舍

- 本轮修复同一工作台中的并发入口及过期回包，不声称后端所有维护写入已具备 PostgreSQL 多客户端并发保护；托管真实并发保留独立待验证风险，不连主库。
- 忙碌状态短暂暂停相关写入口，不引入新的制作确认流程，不改变已确认播放器视觉或时间线保存队列。
- 读取只替换同一项目中基准仍匹配的目标产物，保留对话消息、当前选中产物和未发送文字；不静默换基准后再次覆盖。
