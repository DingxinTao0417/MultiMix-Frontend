# 资源库跨类型验收与交互状态统一计划

> Status: archived
> Owner: frontend
> Last verified: 2026-09-17

## 背景与根因

图片详情已经完成桌面浏览器验收，但文案、视频和资产三类详情尚未用稳定的真实结构数据逐一检查；搜索无结果与真正空库目前共用“这个分类还没有内容”，加载更多也只有孤立按钮，用户无法判断是库为空、筛选无命中，还是还有下一页。

本轮先补齐四类资源的一致性验收，再统一搜索、筛选和分页状态。按用户确认，本轮明确不设计、不验证、不修改“打开剪辑器”。

- `app/globals.css:5890-6110, 6570-6880, 8180-8260`：筛选反馈、分页反馈、详情视觉与状态卡。

## 已锁定设计

- 文案、视频、资产详情继续复用已确认的统一弹窗骨架；只检查各自内容是否完整、可读、可滚动。
- 视频详情保留“用于创作、加入项目、下载、重新解析、导出口播稿”等现有能力，但本轮完全排除“打开剪辑器”。
- 真正空库继续显示“这个分类还没有内容”；存在搜索词或非默认筛选时，改为“没有找到匹配内容”。
- 无结果状态提供单一“清除搜索和筛选”动作，恢复当前库默认视图，不自动切换资源库。
- 存在下一页时，列表底部显示“当前显示 N 项”和“加载更多内容”；N 仅代表已加载并正在显示的条目，不冒充总数。
- 加载下一页时按钮文案改为“正在加载更多…”，并保留原有失败提示与重试路径。

## 风险与取舍

- 跨类型浏览器夹具只用于确定性 UI 验收，不改变后端数据结构或生产接口。
- “当前显示 N 项”是当前客户端视图数量，不代表服务端资源总数，文案不能简化为“共 N 项”。
- 清除动作只复位当前库的关键词、分类和状态筛选，不改变用户所在库。
- 视频详情可能包含视频工程数据，但本轮不得把“打开剪辑器”纳入完成标准。
