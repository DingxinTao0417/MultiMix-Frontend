# 工作台整页滚动修复

> Status: active-plan
> Owner: frontend
> Last verified: 2026-09-28

## 背景与根因

主页及 `/app/assets` 共用工作台。截图显示浏览器整页可向下滚动，工作台下方露出空白。`app/globals.css:75-83` 的根文档只设 `min-height`，未建立工作台页面的视口滚动边界；工作台自身在 `:106-148` 为 `100svh` 且裁切内容，内部对话滚动在 `:1663-1685`。因此外部溢出仍可能使浏览器文档成为滚动容器。前端设计 `docs/MULTIMIX_WORKSPACE_DESIGN.md:68` 要求页面占满视口；`:438` 所述展示区自然滚动属于内部内容区，不应产生整页空白。

## 修改范围与方法

1. 在 `app/globals.css` 为直接包含工作台根节点的 `body` 及其 `html` 建立 `100svh` 高度和 `overflow: clip`，仅约束工作台页面，不影响登录、管理和剪辑器页面。首轮浏览器验证显示仅约束 `body` 后，根文档仍可滚动，因此需同时约束 `html`。
2. 不改工作台内部 `.shadcn-prototype-thread`、分镜展示区和资源列表的滚动规则。

## 风险与取舍

- 浏览器整页滚动被禁用后，超长内容必须依赖既有内部滚动区；需在桌面及窄屏核对可达性。
- `:has()` 用于按工作台根节点限定样式，目标浏览器为当前受支持的现代浏览器。

## 验证

- L1：浏览器在主页及 `/app/assets` 注入可造成文档溢出的内容后，检查 `scrollY` 仍为 0、工作台仍占满视口；核对内部对话/起始页滚动区可滚动。
- 运行前端相关静态检查与 `docs:check`；不调用付费模型或真实视频链路。

### 结果（2026-09-28）

- 独立 `3218` 前端、无后端或测试库：`/` 与 `/app/assets` 在 `1920×900`、`800×900` 四种组合中，注入外层溢出后 `scrollY=0`、根文档高度 `900`，起始页内部 `scrollTop=1000`。
- `npm run typecheck`、`npm run lint`、`npm run build`、`npm run docs:check`、`npm run test:fast` 通过。首轮 `test:fast` 因临时 Next 实例改写 `next-env.d.ts` 的类型目录而失败；构建恢复为受支持目录后复测通过（1125 个 Vitest、8 个 demo unit、253 个脚本测试通过，1 个跳过）。
- 未执行真实对话内容 E2E、视频生成或付费链路；结论限于页面滚动边界及现有离线回归。

### 补充复核（2026-09-29）

- 使用隔离的本地 SQLite 夹具，经产品页面和公开接口加载已保存的编导稿对话；生产构建已包含本次 CSS 修改。`1920×900`、`1280×720` 两个视口均测得 `window.scrollY=0`，根文档高度与视口高度一致，工作台外壳高度与视口一致。
- 本次对话内容不足以触发对话区自身滚动；内部滚动可用性的结论仍以 2026-09-28 的起始页浏览器验证为准。
- 一次性数据库、测试产物和本次启动的前后端进程已清理。现有生产标签页的后端未连接，未进行线上对话验收，也未部署本次修改。
