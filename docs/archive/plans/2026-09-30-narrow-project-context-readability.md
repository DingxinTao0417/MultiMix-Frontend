# 窄屏项目标题与资料名称可读性修复

> Status: archived
> Owner: frontend
> Last verified: 2026-09-30

## 背景与根因

2026-09-30 的隔离浏览器复测确认两个 P2：390px 宽度下已有项目标题只剩约 76px，显示成 `CASE-0…`；320px 的项目资料抽屉里，真实素材 `测试门店素材` 只显示开头。前者是标题双行布局只在 `max-width: 380px` 生效，381px 起又回到同一行争抢空间；后者是资源条目在窄屏仍使用 `minmax(0, 1fr) auto` 双列，三个操作按钮优先占满右列。两处均属于内容空间分配问题，不涉及资源数据或播放器。

## 涉及文件与关键行

- `MultiMix-Frontend/app/globals.css:3174-3204,3441-3528,12046-12063`：对话头、资料条目及窄屏覆盖样式。
- `MultiMix-Frontend/e2e/display-area.spec.ts:53-129`：现有标题断点回归只检查 `<=380px`，且资料数量由路由模拟，未验收真实素材名称。
- `MultiMix-Frontend/docs/MULTIMIX_WORKSPACE_DESIGN.md:229`：项目资料入口在窄屏的位置规则。

## 具体改法与任务

1. 设计落盘与占用登记：在此记录修复边界，确认与其他开发任务无冲突，再写代码。
2. 最小布局修复与回归：把标题双行模式覆盖到项目名具备实际可读空间的手机宽度（计划 `<=520px`）；资料抽屉在 `<=380px` 改为素材身份在上、操作在下的单列条目，不隐藏或替换既有管理动作。扩展隔离 E2E 至 390、430、520/521px，并以真实 CASE-02 已保存素材检查窄屏名称没有被截断。
3. 验证收口：运行静态检查、文档检查、播放器保护检查和隔离浏览器 E2E；查看 320、390、520、1280px 截图与交互，核对临时数据库和进程清理。

## 风险与取舍

- 手机宽度的标题头会增高一行，换取完整项目识别；桌面头和播放器不变。
- 资源操作在窄屏增高卡片，不把危险操作藏进新菜单，保持现有可访问性与确认流程。
- 超长自定义标题仍允许合理省略，但常见项目名不应只剩一两个词。断点附近要验证无跳变造成的操作丢失。
- 本轮不改变资源 API、状态、数据库、视频预览外壳或业务数据；此前未提交的窄屏修复继续保留，避免覆盖。
