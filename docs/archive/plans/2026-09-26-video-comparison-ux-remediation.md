# 视频版本对比交互与可见性修复

> Status: archived
> Owner: frontend
> Last verified: 2026-09-27

## 背景与根因

当前双播放器按分镜起点跳转，但新增/移除分镜在另一版没有对应时间时仍显示旧帧，并沿用用户先前选择的试听音轨；界面同时宣称“已同步定位”。差异列表在 1280×720 首屏落到视口下方。差异摘要还会由素材标题变化直接推断“素材已更换”，且未交代全片音乐等非分镜变化，削弱验收可信度。

## 具体改法

1. 新增/移除镜选中时仅定位存在该镜的一侧，另一侧暂停并明确覆盖“此版无对应分镜”，不再把残留帧当成对应内容；试听自动落到存在的一侧，无法切换至缺失侧。匹配镜仍允许单音轨切换。跳转文案只承诺本次定位，不承诺持续同步；播放失败给出可见提示。
2. 矮屏保留可辨认、可播放的双完整播放器与受保护白色外壳。真实 1280×720 工作台验证表明，即使将竖屏播放器缩到 210px，首张差异卡仍在 y≈888，继续强压播放器会牺牲观看能力。因此首屏改为明确提供“查看受影响分镜”锚点；点击后滚到唯一差异列表，再点击分镜时把双播放器带回视野并定位。窄屏保持可滚动、无横向溢出，不复制第二组卡片。
3. 素材身份只依据权威 `asset_reference` 标识判断；仅有名称变化时显示“素材信息已调整”并列出前后名称，不断言素材已更换。添加有依据的全片变化摘要（如 BGM、画幅），和分镜差异共用一块轻量说明，不增加第二套卡片。
4. 明确“版本对比 · N 处改动”的计数含义，并说明修改后是已保存的当前版，复核不等于二次采用；历史版本仍从现有详情入口查看。

## 风险与取舍

- 旧快照可能没有权威素材 ID 或 BGM 信息；缺失时不猜测，不用标题或缩略图假装身份变化。
- 两版完整视频仍各有自身时间线，无法保证播放过程帧级持续同步；本轮仅保证选镜后的起点定位和单音轨规则，文案必须与能力一致。
- 矮屏只做适度的对比专属密度控制，不为强求首卡露出而继续缩成难以观看的小播放器；首屏可发现差异入口，卡片需要一步滚动。通用播放器外壳、画布比例、控制条和单视频布局不变。
- 不改后端持久化、版本确认门与已保存版本状态；本轮不新增“采用此版”操作。

## 验证方式

1. 先写回归用例：正常匹配镜、先切到旧版音轨后选新增镜、选移除镜、播放失败、仅标题变化与可信素材 ID 变化、BGM/画幅变更。
2. 运行相关 Vitest、`npm run typecheck`、`npm run lint`、`npm run docs:check`、`git diff --check`。
3. 用真实本地页面在 1280×720、1440×900、窄屏验证双播放器、首屏差异入口→差异列表→选镜返回播放器的闭环、试听与缺失侧遮挡，保存截图。若需独立 E2E 后端，仅用预先告知路径的一次性 SQLite 和独立端口，并清理进程与测试库。
4. 如触及受保护的展示链路，运行 `npm run check:video-preview-contract`、`npm run test:product-stage-style` 与隔离的 `npm run test:display-coverage`；已知基线失败与新回归分开报告。
