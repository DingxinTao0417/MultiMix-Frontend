# 图片与视频库展示修复

> Status: archived
> Owner: frontend
> Last verified: 2026-10-09

## 背景与根因

用户本轮确认：失败的视频工程不应混入视频库；每条视频应有真实缩略图；图片库统一方形预览。

- `app/assets/lib/asset-workspace-adapter.ts:2146`：列表和检索按 library_kind 直接展示，没有以服务端 product_status 限定工程完成态。
- 同文件约1390行：封面只读取 thumbnail_ref/thumbnail_url/poster_url，遗漏 poster_ref 及工程内封面。历史原视频没有已保存封面时，列表统一显示“视频预览”。
- `app/globals.css:6940,7066,7080,7353,7445`：图片4:3与媒体内部固有尺寸参与网格高度计算，竖图拉高卡片且同排卡片被拉伸。

## 具体改法与边界

1. 工程仅在服务端 `product_status=completed` 时进入视频库列表和关键词/语义检索；失败和生成中的记录仍在原项目读取、恢复、重试，不删除或自动归档历史数据。已上传原视频保留现有入口，理解失败不等于媒体生成失败。
2. 统一封面引用读取已有thumbnail/poster字段；缺少封面的可播放历史视频在进入视口后由产品浏览器读取真实帧，最多两个同时解码，完成/失败/取消后释放媒体。已有封面不请求视频。不写数据库、不产生AI调用，不以其他图片冒充视频帧。封面加载失败时尝试同一视频帧；确实不可读时明确显示“封面暂不可用”。
3. 图片库固定1:1媒体区域，居中cover裁切仅用于列表；详情与下载保留完整原图。媒体脱离固有尺寸撑高，卡片按自身内容自然高度，视频保持16:9。
4. 分页用原始数据偏移；跳过全被排除的页面后仍能到达后续完成工程，不因过滤产生无法“加载更多”的空页。搜索与普通列表共用资格判断。

## 风险与取舍

- 失败工程必须保留以满足确认幂等和恢复合同；本轮修复的是资源库收录展示边界，不能删除工程占位。
- 未记录完成态的旧工程不推测已完成；仍可通过原项目查看。
- 浏览器无法解码、跨域限制或源文件不存在时如实显示封面不可用；不自动修改素材或批量回填。
- 历史取帧是只读展示兼容；后续上游持久化封面覆盖全部视频时可移除该兼容。消费者仅资源库缩略图，Owner frontend。
