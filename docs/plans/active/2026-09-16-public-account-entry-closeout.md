# MultiMix 公开账号入口与 UI/UX 验收收口计划

> Status: active-plan
> Owner: frontend
> Last verified: 2026-09-16

## 背景与根因

2026-09-14 的 UI/UX 整改已经统一菜单、对话区、展示区与移动结果查看，并完成生产只读复测。公开上线总任务仍有三处没有形成闭环：登录页的协议文字不可访问且注册没有显式同意版本；“忘记密码”只发送邮件，没有指定回跳地址、设置新密码页面或恢复事件处理；跨仓 UI/UX 评审报告尚未纳入版本控制，也没有记录最近一轮生产验收证据。

根因是上一轮把账号与法律入口作为独立上线依赖保留，生产验收只覆盖登录后的作品展示状态，没有继续完成账号恢复与公开协议页面。

## 范围与文件

- `app/multimix-app.tsx`：登录/注册协议入口、注册显式同意、同意版本元数据、密码恢复回跳。
- `app/auth/reset-password/page.tsx`：恢复链接落地、恢复会话校验、两次密码确认和更新成功反馈。
- `app/legal/terms/page.tsx`、`app/legal/privacy/page.tsx`：公开可访问、可保存、带版本与生效日期的协议页面。
- `app/styles/login-shell.css`、新增法律页样式模块：保持现有暖白视觉语言，并补齐焦点、窄屏和状态反馈。
- 聚焦测试与 `app/assets/__tests__/agent-ui-copy.test.ts`：锁定恢复回跳、更新调用、协议链接、显式同意和版本元数据。
- `MultiMix-Backend/docs/qa/2026-09-14-ui-ux-public-launch-review.md`：追加本轮截图、生产验收结果、残余风险与最终结论。

不改支付、积分、商户申请、付费生成、素材或视频编排，不触发生产删除、生成或付费操作。正式运营主体、地址和对外联系邮箱若没有现成权威信息，不在代码中猜测。

## 具体改法

1. 为服务条款和隐私政策建立独立公开路由，写清免费测试阶段的服务边界、用户内容权利、禁止行为、AI 输出校验、账号终止、信息类别、处理目的、保存、共享/委托、跨境可能性、用户权利、安全和未成年人规则。重大利害条款使用独立提示样式，并保留法务复核标记在仓库文档中，不把内部标记显示给用户。
2. 注册模式增加未预选的显式同意复选框；提交前阻止未同意注册。Supabase 注册把 `legal_consent_version`、`terms_version`、`privacy_version` 和 ISO 时间写入用户元数据，作为当前阶段的同意版本记录。该元数据不是支付或不可篡改审计账，商业化前仍按收费母计划建设服务端账本。
3. 忘记密码调用显式传入同源 `/auth/reset-password` 回跳。恢复页监听 `PASSWORD_RECOVERY` 并同时校验已有恢复会话；仅在有效会话下允许调用 `updateUser({ password })`，成功后清理恢复状态并引导返回登录。
4. 先用聚焦静态合同和组件测试覆盖关键分支，再运行类型、lint、docs/agent 合同与构建。部署后只读检查协议路由、登录注册入口、窄屏和恢复落地页；真实邮件和密码变更由用户提供 QA 账号并在最终提交新密码前接管。
5. 将评审报告更新为最终状态，附本轮截图与生产部署证据；计划完成后移入 `docs/archive/plans/`，按双仓提交门禁提交、推送并核对远端与生产版本。

## 风险与取舍

- 法律文本必须匹配真实主体、联系渠道、服务商和数据流；缺少主体信息时不得用虚构公司或邮箱替代。空字段不等于法律合规完成，商业化前仍由经营负责人或律师复核。
- Supabase 恢复邮件的 `redirectTo` 必须在项目 URL allow list 中；代码正确不能替代生产配置核对。
- `user_metadata` 可满足当前免费测试阶段的版本可追溯需求，但不能替代商业化所需的服务端不可变同意记录。
- 真实密码恢复会改变账号凭据并发送邮件，最终验收使用独立 QA 账号；不使用主账号进行自动化改密。

## 事实核对（2026-09-16）

- 产品当前是面向本地商家的对话式 AI 短视频工作台，公开版本仍处于免费测试与付费准备阶段；本轮不发布收费、积分包或自动续费承诺。
- 账号、会话、数据库和对象存储使用 Supabase；前端部署在 Vercel，后端与任务服务部署在 Railway；创作链路按实际配置可能调用阿里云百炼、OpenAI 兼容模型服务、Modal，以及 Pexels/Unsplash 公共素材源。
- 用户输入包括邮箱、对话需求、上传的图片/视频/文档、生成配置、反馈与创作产物；服务运行还会产生登录、任务、错误、用量和安全日志。
- 项目没有 `.agents/startup-context.md`，也没有可用于公开页面的正式运营主体、注册地址或对外法律联系邮箱。法律页面可以先完成结构与真实数据流，生产发布前必须由用户补齐这三项并完成经营/法务复核。
- 密码恢复使用 Supabase PKCE；官方流程要求发送邮件时指定允许的回跳 URL，在公开恢复页取得有效会话后调用 `updateUser({ password })`。生产还需核对 URL allow list 与 SMTP 可用性。
- 法律依据以《个人信息保护法》第十七条的显著、清晰、完整告知要求，以及《民法典》第四百九十六条的格式条款提示义务为起草基线；这不是法律意见。

## 用户决策（2026-09-16）

- 用户明确要求正式运营主体、注册地址、法律/隐私联系邮箱暂时留空，并以此完成本轮 UI/UX 任务闭环。页面使用“—”表示空值，不写入虚构主体或邮箱。
- 本轮把“公开路由、可读结构、注册显式同意、版本记录和密码恢复产品路径”作为 UI/UX 验收范围；主体信息完整性保留为商业化/法律准备事项，不继续阻塞代码提交与部署。
- 用户没有提供独立 QA 邮箱。本轮生产验收只检查恢复入口、回跳路由和无效链接状态；有效恢复会话由组件测试覆盖。真实邮件、用户接管提交新密码与旧密码失效不再作为本轮提交门槛，继续作为账号运维复测项记录。

## 验证方式

- 聚焦测试：协议链接、注册同意门、同意版本、恢复回跳、恢复事件、密码一致性、更新成功/失败。
- 静态检查：`npm run typecheck`、`npm run lint`、`npm run check:agents`、`npm run build`。
- 浏览器：桌面与 390px 窄屏检查登录、注册、条款、隐私、无 token/失效 token/有效恢复页；截图归档到工作区 `artifacts/qa/`。
- 生产：显式核对 Vercel team `lywgood96-1172s-projects`、project `multimix-frontend` 与 `https://multimix-frontend.vercel.app`，部署后只读复测公开路由和登录入口。真实恢复邮件与改密单独记录，不触发任何生成、删除或付费操作。
