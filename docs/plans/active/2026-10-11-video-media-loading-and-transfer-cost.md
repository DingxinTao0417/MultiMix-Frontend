# 视频加载速度与转送成本优化

> Status: active-plan
> Owner: frontend
> Last verified: 2026-10-11

## 背景与证据

用户要求继续优化视频加载速度和转送成本。已发布的完整媒体合同仍是唯一预览/导出入口；不改变视频、字幕、质量门、工程或播放器样式。

- 前轮 Chrome：完整视频 36,077,615 bytes / 122,402 ms，音频 765,203 bytes / 1,360 ms；实际播放到 30.60 / 30.631 秒。
- 同一窗口 Railway 原视频 35 个 GET 全为 206，累计 totalDuration 13,112 ms。其余 109,290 ms 不在该后端计时范围内，不能直接归因于带宽或跨区延迟。
- `editor-engine/vendor/bootstrap.ts:16,211,334,494`：默认 1 MiB，逐块串行；工程初始化和更新均重新获取全部素材，即使已注册原文件身份未变。
- 官方部署元数据 regions=[iad1]；唯一生产 Railway API 在 sin。该地域差异是可验证的延迟风险，不把它直接宣称为全部等待的根因。
- `lib/video-media-relay.ts:2,41` 当前限制 1 MiB；媒体读取由后端逐次验证已签发的用户/工程/原文件/身份/期限合同。

## 方案与取舍

采用有限前端优化：扩大块、媒体路由靠近后端、当前编辑页面内复用完整原件。保留完整 File 和现有 60 秒无进展 / 5 分钟总期限。暂不增加并发，不截断或转码原视频，不引入公共 CDN、跨页面持久缓存或后台预取。

1. 客户端默认和服务器最大闭合 Range 共用 3 MiB 常量。36,077,615 bytes 从 35 次降到 12 次，少 65.7% 往返；首次视频字节不变。Vercel 官方函数响应上限为 4.5 MB，3 MiB 留有余量。仍验证 206、逐块范围/总量/MIME/真实 EOF；合法静态媒体完整 200 的既有消费者继续保留，relay 不允许 200。
2. 仅 `/api/video-media/[...path]` 指定 Node.js / preferredRegion=sin1，靠近唯一生产后端；不更改其它路由或项目全局地域。必须在后续部署产物确认该设置生效；本地配置不能当作生产地域已变更。
3. 当前编辑上下文保存完整、校验通过的 Blob，最多 64 MiB / 8 项、固定 5 分钟且不超过原授权期限；页面离开/显式 dispose 清空，编辑器内部重新初始化保留有限缓存。页面刷新或 iframe 重建不保证命中。
4. 缓存索引只使用后端正常返回签名载荷里的用户、工程、文件、身份；该载荷是未验证的索引提示，绝不作为授权依据。每次命中先用当前地址请求 `bytes=0-0`，由原后端重新核验签名/期限/归属/引用/文件身份，再核验 206、精确总量、MIME、长度和首字节一致。拒绝、错误或不一致立即清掉此项并停止，不悄悄重试或使用缓存。身份或用户不同直接重新下载；未注册/BGM 不缓存。
5. 缓存清理递增生命周期代数，已清理或用户切换前的在途下载不能重新写入；失败/半文件永不入缓存。诊断仅增加枚举 cache 和数字 requestCount/transferredBytes，不记录 URL、token、文件名、用户或作品身份。

### 成本边界

- 冷读仍约 36.08 MB；减少请求仅影响请求/调用开销，不能等同于账单同比下降。
- 同一编辑页面内、期限内、身份不变且服务器核验成功时，重复视频正文从 36,077,615 bytes 降为 1 byte；这是命中场景的传输量目标，不能冒充全月费用节省。
- 实际命中率、首次耗时和地域生效须生产有限复测；不承诺具体加速倍数或美元节省。
- Vercel 转送依然是网络故障期间的隔离方案；外部直连根因未确认，此优化不称其已解决。删除条件沿用已归档超时整改记录。

先 L1 红→绿：真实 Response/ReadableStream 的完整 36,077,615 字节拼装 / 12 请求；3 MiB 允许而超限拒绝；缓存命中仍核验服务器、拒绝后不能复用、身份/用户/到期/容量/生命周期隔离；总期限及失败发布边界保持。L2：既有 bootstrap/buildProject/serializeProject、BGM、编辑器生命周期/导出测试；再运行 typecheck、lint、test:fast、check:agents、build。不得为通过测试修改无关失败或扩大提交范围。

生产复测属于新 L3：用户在本轮明确授权“允许推送并发布视频加载优化，按30次请求上限只读复测一次现有工程，继续”。复用现有工程/原片/音频/字幕，先重新核对其指纹与普通用户只读可访问性，最多一次正常预览冷读；不恢复归档项目、不更改作品/字幕、不调用模型。共享账本截至2026-10-10T18:51:05Z为1251/1482、余231，字幕会话确认其后0新增应用HTTP；本轮新增后端HTTP硬上限30，仍受USD1共享上限约束。预算或指纹不足停止；冷读失败立即停止，不盲重试。

消费方复核（2026-10-11）：浏览态预览重试及切换预览/剪辑器会新建 iframe，不能命中当前编辑上下文缓存；现有 `ReplacePanel` 在用户明确修改素材后刷新同一编辑器是实际复用消费者，但该修改不在此次只读复测范围。没有普通用户可用的同上下文只读重新装载按钮，因此本轮缓存命中只给 L1/L2 证据，不调用内部函数制造生产热读。跨 iframe/刷新复用需要独立媒体交付设计，不宣称本轮已解决。
