## 目标与当前状态

在取得真实作品、质量结论和首页公开展示授权后，先上架 1–2 个案例，让非专业用户先看到最终成片，再按需查看制作过程；随后按前端发布流程验证并发布首页。案例数量不凑满三条。

首页结构已在 `MultiMix-Frontend/docs/archive/plans/2026-09-29-homepage-showcase-structure.md` 完成并本地验证；本计划立项时相关前端文件尚未提交，执行前须重新核对实际提交基线。`app/assets/lib/homepage-showcase-cases.ts:21` 的正式案例清单为空，`app/assets/components/homepage-showcase.tsx:18-29` 在无合格案例时隐藏整个区域。内部 QA 成片不满足首页公开展示条件，详见 `MultiMix-Backend/docs/qa/video-golden-baseline-evidence.md`。因此本计划不能从现有 QA 文件中直接挑视频上线。

本计划只负责首页真实案例的内容准入、前端接入与前端发布。成片制作能力、素材理解或视频生成链路的整改仍归现有跨端计划；若接入时发现必须修改后端接口或存储契约，先停止前端实施，更新范围并落入跨端计划。

## 开工前提

1. 用户明确要求恢复执行本计划，并提供或指定可审查的案例候选。记录候选对应的 MultiMix 产品原生运行、输入、最终视频、版本及过程证据；不能由 Codex 补造视频或制作记录。
2. 每个候选都有完整观看后的质量结论，以及成片、原素材、人物形象与声音、音乐、商标和品牌在 MultiMix 首页公开展示的授权范围。展示原片作前后对比时，还须单独确认原片的公开展示权限；没有则只展示最终成片。
3. 核对候选视频、封面和过程摘要与同一个最终版本一致，确认公开展示不会泄露私人聊天、客户资料、联系方式或内部测试标记。授权不明确、内容质量未通过或来源不可追溯时，该候选不上架。

## 实施任务与完成门槛

1. [ ] **基线与范围确认。**核对当前分支、未提交首页改动、并行开发占用和前端发布基线；为本计划登记具体 `area` 与 `path`，避免覆盖其他任务。完成门槛：明确本轮实际修改文件、提交边界和回退版本。
2. [ ] **案例候选准入。**为每条候选保存产品原生制作证据、最终视频身份、完整人工审片结果、首页公开授权及原片可否展示的结论。完成门槛：至少一条合格；不足时停止上架，正式页面继续隐藏案例区。
3. [ ] **内容与媒体准备。**从真实记录编辑“用户提供 → 最终成果”和“需求 → 方案 → 修改 → 成片”的简短过程；校对案例名称、入口归属、封面及视频来源，确认稳定可公开访问的媒体位置。完成门槛：文案、封面、成片和授权都对应同一候选版本。
4. [ ] **前端接入。**把合格案例接入正式清单；按实际内容修正必要的展示问题，并保持零案例隐藏、原片可选、视频不自动播放。完成门槛：无假案例、无未授权原片、无私有地址或内部测试标记进入构建产物。
5. [ ] **验证与审片。**先跑案例筛选和组件 L1 测试，再按影响范围跑相关回归、`typecheck`、`lint`、`test:fast`、`build`、`docs:check`。在预览环境用真实获准媒体检查桌面与手机布局、弹层、键盘关闭、完整播放、封面、媒体错误与无横向溢出；人工再次完整观看实际待发布视频。完成门槛：记录实际通过范围，不能用组件测试代替公开媒体播放或成片质量结论。
6. [ ] **提交、发布与观察。**只提交本计划相关文件并按工作区单写入提交门禁处理；推送和生产部署须在用户随后明确授权的范围内执行。生产前显式核对 Vercel team `lywgood96-1172s-projects`、project `multimix-frontend` 和 `https://multimix-frontend.vercel.app`，不得沿用旧项目。上线后检查真实页面和视频播放，记录版本与回退方式；若媒体、授权或展示出问题，立即移除该案例并恢复已验证版本。完成门槛：生产地址核对、案例实际可用、发布记录及回退点齐全，随后归档本计划。

## 风险与取舍

- **权利与隐私：**测试授权、客户交付授权和首页营销展示授权不能互相替代；记录缺失即不上架，不用模糊文案掩盖来源。
- **质量与能力表达：**首页只展示真实完成的结果和真实发生的修改，不把单例包装成所有类似任务都能稳定一次完成。人物口型、参考片复刻等尚未获首版验收的能力不能因案例文案变成普遍承诺。
- **媒体交付：**视频 URL、封面、缓存、浏览器兼容性或流量成本可能影响实际播放。媒体承载方式在候选体积和公开范围明确后确定；不能先把大文件或短期签名 URL 填入首页。
- **并发与发布：**当前工作区存在其他未提交修改；不得用 `git add -A` 收入无关文件。前端案例发布不自动触发后端部署，也不自动执行付费视频全链路测试。
- **空状态：**没有合格案例时维持当前隐藏策略，不能为了如期发布放入原型占位或内部 QA 成片。

## 验证层级与执行边界

本轮只新增计划文档，不启动制作、上传、代码修改、测试视频生成、提交、推送或部署。将来实施默认从 L1/L2 开始；如果需要重新生成真实案例或验证跨阶段视频主链，先按 `MultiMix-Backend/docs/authority/test-scope-and-cost-control.md` 记录 L3/L4 原因、可复用 checkpoint 与外部调用预算，再在获准范围内执行。发布后的检查只能证明实际上架的案例与首页体验，不能推出整个 MultiMix 视频能力已全面达标。
