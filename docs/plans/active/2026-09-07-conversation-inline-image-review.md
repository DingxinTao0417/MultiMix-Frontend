# 对话内图片关键帧组与默认审核栏

> Status: active-plan
> Owner: frontend
> Last verified: 2026-09-07

## 背景与根因

当前生成图片只在右侧 `ProductWorkspace` 中通过 `ProductPreview` / `GeneratedImageGallery` 展示。对话区只显示生成过程和可打开右侧产物的文字入口，导致用户在“提出修改 → 查看图片 → 根据图片继续调整”之间反复跨区域切换。

现有 `GeneratedImageGallery` 已能读取同一生成任务的多张 `generated_images`、记录当前选中帧并显示每帧 `quality_review`，但它把主图、审核文本、应用动作和缩略图堆进单一卡片；审核信息没有稳定的独立视觉区域，也没有把这一组关键帧作为对话中可追溯的生成结果呈现。

用户已确认采用方案 B：图片直接显示在对话中；审核栏默认出现；一次生成可包含多张关键帧。

## 已确认的产品与交互设计

1. 每次成功生成图片，在对话流中渲染为一个“关键帧组”产物卡，而不是只给出跳转右侧的文字提示。
2. 关键帧组显示该批次标题、图片数、批次摘要状态，以及所有关键帧缩略图。缩略图需要显示每帧独立的可用/待确认状态与最重要的一句结论；选择任意帧不改变生成结果或写入服务端。
3. 右侧展示区在图片产物选中时固定显示默认展开的审核栏：当前选中关键帧、最多 2–3 条关键差异、通过项摘要、原图与继续调整动作。无异常时仍显示“已通过 / 仍需人工确认”的轻量结论，不能变为空白。
4. 对话内卡片是生成上下文与快速切换入口；右侧是当前关键帧的大图审阅和操作舞台。两侧的选中帧必须同步。
5. “继续调整此图”复用现有对话输入和图片生成确认/任务链路，携带当前产物上下文；不增加新的后端 API、生成状态或确认门。
6. 下载、保存、应用到封面/分镜等已有动作继续沿用已有权限和目标校验，不因移动展示位置而改变可用性或幂等语义。

## 涉及文件与关键位置

- `app/assets/components/generated-image-gallery.tsx`：第 7–120 行。抽取并复用 `framesFrom`、状态标签、选中帧和检查结果的展示模型；将紧凑关键帧组与审阅视图拆为有明确输入/输出的组件，避免两处各自解释 `quality_review`。
- `app/assets/components/conversation-studio.tsx`：消息渲染与产品卡关联区域（约第 1100–1150 行）。为图片生成成功消息插入可选中关键帧组，并把用户的选择上抛给工作台状态，而不是把完整大图和审核长文重复塞进普通聊天气泡。
- `app/assets/components/assets-workspace-client.tsx`：第 628 行附近的 `selectedProductIds`，以及第 3040–3160 行的对话区/右侧 `ProductWorkspace` 组合。新增按图片产物保存“当前选中关键帧”的受控状态，并在对话卡与右侧审阅区之间同步；不修改服务端持久化的产品定义。
- `app/assets/components/product-preview.tsx`：第 348–376 行图片生成产物分支。接收受控选中帧、展示右侧主图与默认审核栏，并把继续调整/已有应用动作回调到既有父级能力。
- `app/globals.css`：第 4124 行附近的图片卡样式。新增对话内关键帧组、默认审核栏、缩略图状态和窄屏降级样式；不改视频播放器受保护选择器或视频视觉契约。
- `app/assets/components/__tests__/generated-image-gallery.test.tsx`（如现有测试覆盖不足则扩展）以及对话/展示区相关测试：验证多帧选择同步、审核栏默认渲染、通过与待确认状态、只读快照和无权限时动作禁用。

## 具体实施步骤

1. 先写失败测试，覆盖多关键帧生成结果：默认选择首帧、选择另一帧后对话卡与右侧审核一致、每帧只显示其自身的检查结论。
2. 将图片帧解析、标签和问题筛选收敛为共享展示模型；保留现有未知/缺失检查数据的安全文案与人工确认提示。
3. 实现对话内关键帧组和受控选中帧状态，并接入现有消息—产品关联；保留非图片产物的当前行为。
4. 改造右侧图片预览为“主图 + 默认审核栏”，复用现有原图、保存和应用动作，不复制业务写入逻辑。
5. 补齐响应式样式：工作台宽度足够时对话与审核栏并列；窄屏时审核摘要随选中帧显示为可访问的紧凑区，不能丢失关键结论或操作。
6. 运行单元/展示区检查与浏览器验证，重点检查多帧切换、待确认/通过、快照只读、生成中与图片不可读等状态。

## 风险与取舍

- 对话中重复完整图片会造成滚动膨胀。因此对话卡展示关键帧组缩略图/有限预览，右侧保留唯一大图审阅舞台；不采用“所有图片只留在聊天里”的方案。
- `quality_review` 可能缺失或返回未知状态。UI 必须稳定显示“待人工检查”，不可将缺失数据伪装为通过。
- 选中帧只属于前端浏览状态。不得把切换缩略图误写为“应用到分镜”或修改已保存产物。
- 本轮不触及后端生成、素材引用或视频渲染链路；不改变图片库条目详情使用居中模态的既有规则。

## 验证方式

- 单元：`GeneratedImageGallery` / 图片产物预览的多帧选择、检查文案与动作可用性；消息关联的图片产物渲染与只读快照。
- 集成：对话中生成一组至少 3 张关键帧，点击每张后右侧大图、状态和检查项同步；“继续调整此图”走既有确认和任务链路。
- 视觉：桌面工作台确认审核栏默认存在、图片不被裁切、长证据文本不挤压主图；窄屏确认可读取所选帧的状态与关键差异。
- 回归：`npm --prefix MultiMix-Frontend run lint`、相关 Vitest 测试、`npm --prefix MultiMix-Frontend run test:display-components`、`npm --prefix MultiMix-Frontend run docs:check`。若改动展示区 E2E 覆盖，补跑对应的 `test:display-coverage`。
