# MultiMix 工作台设计文档

状态：待产品确认草案（2026-07-08 修订：库列表状态标签与库详情形态两条约定，按 `../../docs/specs/ui/agentic-workbench-design.md` §10 用户决策更新）

本文档用于沉淀 MultiMix 独立内容生成工作台的产品定位、页面结构、交互规则和数据边界。

这份内容来自 ChangeIn 资产工作台方向，以及 MultiMix 原型设计过程中已经确认过的产品决策。目标是让独立仓库里的协作者不需要阅读 ChangeIn 原始产品文档，也能理解这个页面为什么这样设计、后续应该怎么扩展。

## 1. 产品定位

MultiMix 是一个内容生成工作台，用来把来源素材、结构化市场信号和已生成产物继续转化为可复用的内容产物。

它不是通用聊天页、社交发布工具、文件管理器、爬虫工具或内容农场。核心价值是帮助用户从有来源支撑的输入出发，生成具体可用的交付物，例如文案、图片方向、短视频脚本、MG 动画草稿、实景视频草稿、数字人口播视频草稿，以及音频和字幕时间轴。

这个页面应该像一个创作工作台：

- 对话负责判断用户意图和生成方向。
- 右侧展示当前选中的生成产物。
- 对话中的产物卡负责切换不同产物。
- 详情、参数、来源链路、素材分配等信息保持在次级层级。

## 2. 核心用户流程

1. 用户从一个历史对话进入，或者新建一个创作对话。
2. 用户用自然语言描述想要生成什么。
3. MultiMix 在对话中生成一个或多个产物卡。
4. 当前选中的产物显示在右侧展示区。
5. 助手在对话中给出简短的下一步调整建议。
6. 用户继续通过自然语言调整产物，而不是进入复杂配置面板。

一个对话里应该支持连续生成多种产物，例如：

- 来源素材包 -> LinkedIn 发帖文案
- LinkedIn 发帖文案 -> 封面图
- 封面图 + 脚本 -> 短视频分镜
- 短视频分镜 -> 数字人口播视频

右侧展示区始终只展示当前选中的产物，而不是同时展示所有历史产物。

## 3. 页面结构

桌面端包含三个主要区域：

- 左侧导航：品牌、搜索、新建创作、资产库入口、对话列表、本地账号信息。
- 对话区：用户消息、助手回复、产物卡、下一步建议、输入框。
- 展示区：当前选中产物的完整内容或预览。

页面应该直接占满整个视口。不应该在工作台上方再显示营销 Banner、积分条、MCP 按钮、账号头像或其他和当前创作无关的主工作台头部。

窄屏时侧边栏可以自动收起。自动收起时，不应该留下空白窄轨道。只有用户主动点击收起时，才需要保留可理解的展开入口。

## 4. 导航和资源库

左侧一级资源入口是：

- `资产库`
- `文案库`
- `图片库`
- `视频库`

资产库、文案库、图片库和视频库是不同层级的资源入口：

- `资产库` 承载用户上传、外部采集和对话沉淀的来源资料，后续会接入知识库和检索能力。
- `文案库`、`图片库`、`视频库` 承载已经生成或保存的创作产物。

图片需要作为独立一级图片库，方便封面图、素材图和分镜图沉淀与复用。数字人不是一级资源库，它属于视频的一种表现形式。

对话列表是观察 Mock 场景和产物链路的主要入口。对话行要紧凑，显示对话标题和最近更新时间。重命名、删除等操作放在 hover 菜单里。

### 4.1 资产库分类

资产库的一级分类按来源划分，不按“知识库 / 项目资料”这类容易重叠的概念划分。

资产库分类是：

- `上传资料`：用户从本地上传的文件，例如 PDF、Word、Excel、PPT、图片、视频、音频和压缩包。
- `采集资料`：从外部链接或平台采集来的内容，例如网页、公众号文章、视频链接、行业报告链接和竞品页面。
- `对话沉淀`：从用户和系统对话中沉淀出来的品牌信息、产品卖点、用户画像、风格偏好和历史创作要求。

资产库不显示“用途标签”。内容类型、解析状态、检索关键词和向量索引状态可以保留在数据层和详情层，但不要在列表里堆叠成多个可见分类标签。

资产库列表应该优先展示：

- 标题
- 来源分类
- 内容类型
- 处理状态
- 更新时间

资产详情可以展示：

- 内容摘要
- 原始来源或文件信息
- LLM 提取的检索关键词
- 解析、切片、索引状态
- 最近被哪些创作引用过

知识库是底层能力，不作为用户可见的一级分类。用户看到的是资料从哪里来、是否已可检索、能不能用于创作。

### 4.2 产物库分类

文案库、图片库和视频库只显示已经确认的产物分类，不再显示旧的类型、版本、状态或关键词标签，避免列表看起来像有多套分类体系。

文案库分类是：

- `选题方案`
- `文案稿`
- `编导稿`

图片库分类是：

- `封面图`
- `素材图`
- `分镜图`

视频库分类是：

- `混剪视频`
- `数字人视频`
- `MG动画视频`
- `实景拍摄视频`
- `生成视频素材`

产物列表卡片只显示一个正式分类。标题只保留主题本身，不再把“草稿”“视频文案草稿”“编导稿”等阶段词拼进标题。第二行只显示“正式分类 + 轻状态”，例如“编导稿 · 有来源”。检索关键词可以放在详情弹窗里，供后续搜索和引用，不作为列表标签展示。

用户只粘贴一段长文案或资料时，系统先把它当作待处理素材，不默认判成“要做视频”。应先询问下一步要“生成编导稿”“优化文稿”“提炼封面图文”还是“保存为素材”；只有用户明确说要做视频、生成编导稿或继续视频工程时，才进入视频链路。

点击文案、图片或视频库条目时，详情以居中模态弹窗打开（2026-07-08 规范 §10 决策，覆盖旧详情形态约定）；工作台产物详情仍为顶部「详情」浮层。视频库里的数字人视频详情只展示口播文稿，不展示分镜部分。

### 4.3 资源库条目管理

资产库、文案库、图片库和视频库的条目详情里统一提供基础管理动作，不按库单独设计一套规则。

- `下载`：优先下载用户上传、公开导入或系统保存的原始文件；如果该条目没有原始文件，则下载包含标题、正文和来源引用的 Markdown。
- `删除`：采用软删除/归档语义。删除后该条目从当前库列表、库内搜索和语义搜索中隐藏，但不物理删除底层文件，避免破坏历史对话、来源引用和已生成产物链路。
- 删除前必须有二次确认，确认文案应明确“删除后将从当前库隐藏”。
- 真实后端已连接时，库列表以真实后端返回为准；真实库为空时不要回退展示 mock 示例，避免用户误以为删除失败。
- 这些动作放在详情（模态弹窗）的操作区，不放在列表卡片上，保持列表浏览密度。

## 5. 对话规则

对话是判断以下内容的主要位置：

- 产物类型
- 发布渠道
- 目标受众
- 内容格式
- 画面比例
- 时长
- 风格
- 语言
- 是生成文案、图片、音频、视频、MG 动画、实景视频，还是数字人口播视频

当对话已经理解用户要生成什么以后，右侧展示区不应该再要求用户选择一级 `文案 / 图片 / 视频 / 音频 / 数字人` Tab。

产物生成完成后，助手回复应该简短说明：

- 生成了什么
- 基于什么内容生成
- 用户接下来可以怎么调整

推荐的自然语言调整建议示例：

- `缩短到30秒`
- `换成9:16`
- `把第2段素材换成产品图`
- `改成数字人口播`
- `字幕更大一点`
- `生成一张4:5封面图`

下一步推荐操作优先放在助手回复里，不要在展示区再做一套独立推荐模块。

## 6. 产物卡和产物切换

当一个对话生成多个产物时，每个产物都应该以产物卡的形式出现在对话流里。

点击产物卡，右侧展示区切换到对应产物。

展示区只显示当前选中的产物。上下游关系可以通过以下方式表达：

- 对话中产物卡的出现顺序
- 产物的简短元信息
- `详情` 抽屉

不要为了切换产物，在展示区再增加强制性的产物 Tab。

## 7. 展示区设计原则

展示区是单一的当前产物工作区。

它应该优先做到：

- 完整展示结果
- 预览不被遮挡
- 图片和视频类产物居中展示
- 减少不必要的 UI 装饰
- 保留轻量标题和状态
- 只在需要时显示 `详情`、`复制`、`保存` 等操作

它应该避免：

- 大面积配置面板
- 围绕结果的大块可见边框
- 重复的推荐操作区域
- 默认展示产物结构卡片
- 来源证据和参数信息占据主区域
- 强制用户切换画布、分镜、时间轴、素材、参数等工作视图 Tab

## 8. 不同产物的展示规则

### 8.1 文案产物

文案产物包括：

- 选题方案
- 文案稿
- 编导稿

口播、配音和短视频朗读稿不再单独作为一类展示，统一归入 `编导稿`。当用户只要口播内容时，允许生成不含完整分镜的轻量编导稿。

处理后的素材包也是产物，不是原始素材。它属于基于来源素材二次加工后的文案产物。

文案产物应该在右侧展示区完整展示，方便用户阅读、复制、保存和后续复用。

默认视图不应该是产物结构面板。如果结构、来源、参数或版本信息有价值，应该放进 `详情`。

### 8.2 图片产物

图片产物包括：

- 封面图
- 素材图
- 分镜图

图片预览应该在展示区居中显示。可见边框要尽量少。主区域应该让用户看到图片结果，而不是看到配置表单。

比例、数量、风格、参考素材等轻量控制可以在必要时出现，但大部分调整应该通过自然语言完成。

### 8.3 视频产物

视频产物包括：

- 混剪视频
- 数字人视频
- MG动画视频
- 实景拍摄视频
- 生成视频素材

默认展示应该让视频预览居中。只有当时间轴能帮助用户理解或检查结果时，才在主视图里显示紧凑时间轴。

视频预览必须区分“播放器外壳”和“媒体画布”：

- 播放器外壳使用白底、`1px solid #eae7e1`、`20px` 圆角、`7px` 内边距，以及 `0 2px 6px rgba(32, 31, 30, 0.05), 0 16px 40px rgba(32, 31, 30, 0.07)` 阴影。
- 媒体画布内部可以是黑底、无边框，并按真实素材保持 `9 / 16` 或 `16 / 9`；“媒体画布无边框”不等于“播放器外壳无边框”。
- `9 / 16` 或 `16 / 9` 只约束媒体画布，不约束“媒体画布 + 底部控制条”的整个播放器外壳；控制条必须在画布下方自然增高，禁止挤压或变形媒体画面。
- 浏览态播放器按内容自然占高，后面直接衔接分镜摘要；禁止用固定高度预览容器或独立纵向拖拽条制造播放器下方空白。
- 已有成片播放器与无成片的分镜预览必须共享同一套白色细边框、圆角和柔和阴影外壳；待补素材、首帧未加载和失败提示的默认画布使用白色，只有真实图片或视频加载后才显示其实际画面。
- 底部控制区只保留当前时间、轻量进度条和总时长；播放/暂停由画面中央按钮承担。
- 中央播放按钮固定为 `44px × 44px`，内部播放图标为 `16px`，使用半透明白底和 `0 6px 18px rgba(0,0,0,.25)` 阴影，画面悬停时缩放到 `1.07`。
- 控制区使用 `8px 6px 4px` 内边距、`10.5px` 时间文字和 `8px` 间距；进度轨固定为 `3px`，使用浅灰未播放轨与 AI 渐变已播放轨，不显示浏览器原生滑块。
- 当前交互与视觉基准是工作区根目录 `docs/specs/ui/prototypes/current/screens/workspace-video.html`。
- 这是已确认、不可自动回退的 UI 契约。只有用户在当次任务中明确批准，才能同步修改本节、原型、实现、契约检查和浏览器截图基线。

分镜、素材、音频、字幕、时间轴、渲染状态和参数默认放在 `详情` 中。除非这些内容是理解当前结果的必要部分，否则不要直接占据主展示区。

### 8.4 数字人口播视频

数字人是视频的一种表现形式。

它不应该被当作展示区里的一级产物类型。

默认展示方式：

- 中间展示当前数字人口播视频预览
- 下方在必要时展示逐句音频/字幕时间轴
- 不在预览区显示来源证据卡

数字人口播视频只需要知道它使用的是哪一版文案或口播稿。来源证据、生成链路、人设、字幕设置、渲染信息等都放进 `详情`。

如果需要显示口播稿，默认应该折叠或紧凑展示，避免占用过多视频预览空间。

### 8.5 音频和字幕匹配

音频和字幕匹配通常属于视频生产的一部分，不需要单独成为主场景。

它可以表现为：

- 视频下方的紧凑时间轴
- 逐句时间块
- 字幕匹配状态

如果用户专门处理音频产物，也可以使用同一套模式展示波形和逐句时间，但仍然要避免重边框和复杂配置感。

## 9. 详情（产物浮层 / 库详情弹窗）

`详情` 是承载有价值但不应该占据主展示区的信息的地方。

工作台产物的详情以顶部「详情」浮层打开，不挤压主预览区域；库条目的详情用居中模态弹窗（2026-07-08 规范 §10）。

详情可以包含：

- 生成依据
- 来源链路
- 来源映射
- 素材分配
- 产物参数
- 画面比例
- 时长
- 风格
- 人设
- 字幕设置
- 口播和字幕匹配
- 渲染状态
- 版本信息
- 上下游产物关系

详情回答的是“这个产物为什么这样生成、怎么生成的”。主展示区回答的是“我得到了什么结果”。

## 10. 输入框和调整方式

输入框应该有 AI 原生产品的感觉：

- 默认显示一行
- 内容变多后自动增高
- 不堆叠过多选项
- 圆角边框和阴影明确
- 发送按钮使用简单箭头，并有 hover 效果

助手回复里的建议按钮点击后，应该把对应文字放入输入框。除非动作非常明确且安全，否则不要直接静默执行。

## 11. Mock 数据和本地仓库边界

当前独立仓库使用本地 Mock 数据运行。

应该提交：

- 工作台 UI 代码
- Mock 对话和产物数据
- 真实后端数据契约
- 测试专用最小 fixtures
- 文档

不应该提交：

- 运行时 SQLite 数据库文件
- `.env.local`
- 生产密钥
- 构建产物
- 日志

前端不生成本地 Demo 数据库。API 未配置时显示“未连接后端”，真实后端为空时保持空态，接口失败时显示可重试错误，不回退演示内容。

## 12. 后端接入边界

当前仓库是前端优先的本地版本。

后续接入真实后端时，应该保留当前工作台结构，通过替换 adapter 层来接入真实数据，而不是因为后端实现方式重写 UI。

未来可能接入：

- Supabase Auth：真实用户登录
- Supabase Postgres：持久化对话和产物
- Supabase Storage 或其他存储：保存文件和生成媒体
- Railway API：编排生成任务
- Worker 服务：处理长时间运行的图片、视频、音频任务
- 渲染适配器：对接视频和数字人生成服务

前端不能包含 service-role key、Railway token、Vercel token 或生产密钥。

## 13. 当前需要保留的设计决策

- MultiMix 是独立内容生成工作台。
- 对话决定产物类型和生成意图。
- 展示区直接显示当前产物。
- 展示区不增加一级产物类型 Tab。
- 资产库按来源分类：上传资料、采集资料、对话沉淀。
- 资产库不显示用途标签。
- 资产库里的内容类型、检索关键词、解析和索引状态属于详情层或检索层。
- 文案库分类固定为：选题方案、文案稿、编导稿。
- 图片库分类固定为：封面图、素材图、分镜图。
- 视频库分类固定为：混剪视频、数字人视频、MG动画视频、实景拍摄视频、生成视频素材。
- 文案库、图片库和视频库列表显示一个正式分类；图片库列表卡片同时显示「已解析/待处理」状态胶囊与被引用次数（2026-07-08 规范 §10 决策 1，覆盖旧的「不显示状态标签」约定），仍不显示版本与关键词标签。
- 文案库、图片库和视频库详情用居中模态弹窗打开（2026-07-08 规范 §10 决策 2，覆盖旧详情形态约定）。
- 数字人属于视频模式。
- 数字人视频详情只展示口播文稿，不展示分镜部分。
- 音频和字幕匹配通常属于视频。
- 文案产物也进入右侧展示区。
- 素材包是生成后的文案产物，不是原始素材。
- 详情信息放进详情层（产物=顶部浮层，库条目=模态弹窗）。
- 下一步推荐操作放在助手回复里。
- 对话中的产物卡负责切换右侧展示。
- 本地运行数据库不提交，通过可复现 Mock 数据生成。
