本文档用于沉淀 MultiMix 对话式 AI 短视频创作工作台的产品定位、页面结构、交互规则和数据边界。

这份内容来自历史资产工作台方向，以及 MultiMix 原型设计过程中已经确认过的产品决策。目标是让独立仓库里的协作者不需要阅读旧项目原始产品文档，也能理解这个页面为什么这样设计、后续应该怎么扩展。

## 1. 产品定位

产品定位、目标用户、市场、首发范围及可信要求统一见[产品总纲](specs/ui/product-positioning.md)；本文只定义工作台的页面行为、交互与视觉合同，不另立一套产品定位。

当前登录页和新建页的页面主提示为「说出想法，让 AI 帮你更快、更省力地做出短视频。」；辅助表达为「AI 协助编导和制作；不满意的地方接着聊、局部改，减少返工。」产品总纲中的定位主张不冒充页面已显示文案，实际效果仍待真实任务验证。

用户可以在对话里说明创作需求，上传图片、文档和视频，粘贴受支持的视频链接，或引用已保存素材。视频文件和受支持的视频链接从对话输入框加入；视频库中的原片也先带入同一个输入框。必要资料按任务补齐，素材来源与事实依据仍遵守既有制作合同。

视频准备完成后只显示为对话附件，不立即要求用户选择处理方式，也不自动创建拆条分析。用户说明创作要求后，系统按统一创作画像判断是在制作新作品，还是修改当前原视频，再确定素材用途、声音和逐镜执行方案；不重新分类为“讲解型／口播型”。当前不开放新增长视频拆条入口。

外部视频首次上传但没有附带修改要求时，用户侧只表达已经上传视频，不显示“请先询问我”“暂不开始处理”等面向系统的指令。助手收到视频后再询问是否先把视频整理成便于定位的片段，并用普通语言说明用途；结果产生前不得预设片段数量、编号或修改类型。视频整理进度卡只显示读取、分析、完成、失败和重试状态，不放“把第 2 镜改成动画”等操作教学。完成后的助手说明放在进度卡外，按真实结果说明片段数量，并用“告诉我想调整哪一部分”这类通用表达继续对话。需要用户确认片段划分时，界面必须提供与当前结果和当前修改绑定的明确动作；确认后继续原修改，不重复追问，也不要求用户自行组织专业确认话术。

本页不另增通用聊天、社交发布、文件管理、爬虫或内容农场入口；独立文案与图片能力仍按产品总纲保留。

这个页面应该像一个创作工作台：

- 对话负责判断用户意图和生成方向。
- 展示区展示当前选中的生成产物。
- 对话中的产物卡负责切换不同产物。
- 详情、参数、来源链路、素材分配等信息保持在次级层级。

## 2. 核心用户流程

1. 用户从一个历史对话进入，或者新建一个创作对话。
2. 用户用自然语言说明想做什么短视频，可以从一个想法开始，也可以加入图片、文档或视频。
3. MultiMix 理解素材，生成编导、匹配画面，并默认只公开系统推荐的一版当前结果；编导稿、视频工程等不同生产阶段仍可各自产生产物卡。
4. 当前选中的产物显示在展示区。
5. 助手在对话中给出简短的下一步调整建议。
6. 用户继续通过自然语言调整产物，而不是进入复杂配置面板。
7. 视频实际生成完成后，如系统提炼出可能跨项目复用的偏好，在当前视频结果下方显示一次轻量确认；用户选择保存后才进入创作档案。

一个对话里应该支持沿短视频生产链连续生成多种产物，例如：

- 图片 / 视频 / 文档 -> 编导稿
- 编导稿 + 来源素材 -> 短视频分镜
- 分镜 -> 可编辑视频工程
- 视频工程 -> 修改与导出

用户明确只要文案或图片时，仍可独立生成并保存；这不改变短视频是默认主线。

展示区始终只展示当前选中的产物，而不是同时展示所有历史产物。

新建项目或已有对话尚未形成真实产物时，不渲染展示区和纵向分隔条；对话工作区单栏居中显示。提示词推荐、追问、快捷回答、确认、失败恢复和生成状态都属于对话行为，必须跟随对应的 Agent 消息或工作流卡出现，并复用同一个输入框。上传资料仍由消息附件和项目“资料”抽屉管理，不能仅因存在素材就提前打开产物展示区。

首个真实产物进入当前项目后，工作台再从单栏切换为“展示区 + 对话轨”双栏。展示区承载已经生成且可被选中的编导稿、文案、图片、分镜、视频工程或成片，是桌面工作台的视觉主区；生成中和修改失败时继续显示上一稳定产物，没有稳定产物则保持单栏对话，不使用教程、模板、模拟进度或空白占位填充展示区。

## 3. 页面结构

桌面端在已有产物时包含两个主要区域，工作区占满全宽，不保留常驻侧栏。展示区在左、对话轨在右（2026-10-14 用户确认改向，取代此前“对话区在左”的方案）。**实施状态：本节是已定稿的目标布局，随方案 C 代码改版一起生效；改版前线上实现仍是对话在左、宽度 `clamp(480px, 52%, 720px)`，测试与截图基线按现行实现。**改版计划见 `MultiMix-Frontend/docs/plans/active/2026-10-14-canvas-first-workspace-redesign.md`。

- 展示区：当前选中产物的完整内容或预览，是页面主区，获得剩余空间。
- 对话轨：用户消息、助手回复、产物卡、下一步建议、输入框。

导航不常驻屏幕。对话页、新建项目页和资源库页的页面头部始终提供项目切换器「当前项目名 ▾」，点击或按 `⌘K / Ctrl+K` 打开导航面板。面板复用覆盖式导航：遮罩关闭、Escape、Tab 焦点隔离，关闭后焦点回到打开前的位置；打开时焦点落在项目搜索框。切换页面仍走已有未保存草稿确认，拒绝离开时恢复面板并保留草稿。

- 切换器显示品牌标记、当前位置和 `▾`。对话页的头部已经单独显示项目名，此时切换器不重复显示项目名，可访问名称仍包含它。
- 切换器上的数字角标表示需要处理的项目数，与项目行显示 `生成中 / 待确认 / 需处理` 的项目同源计数，为 0 时隐藏。
- AI 后台任务以紧凑胶囊显示在页面头部（「AI 正在理解素材」，详细说明放在悬停提示和读屏文字中），无任务时整条隐藏。
- 项目列表加载失败时，失败提示与唯一的「重新加载」动作固定显示在页面头部，面板关闭时同样可见、可恢复。

尚无产物时只保留单栏对话工作区；对话本体限制在舒适阅读宽度并居中，不把消息横向拉满，也不保留一块不可用的空白展示区。

有产物时，展示区与对话轨之间保留拖拽分隔条。对话轨默认宽度 `400px`，可拖拽范围 `340–560px`；展示区获得剩余空间，不小于当前上下限约定的最小值。用户拖拽后继续尊重用户选择，但键盘调整、ARIA 数值和拖拽边界必须使用同一组桌面上下限；双击分隔条恢复默认宽度。新增宽度优先分配给展示区，使结果始终是桌面工作台的视觉重心。分隔条只在“展示区 + 对话轨”两栏布局出现：新建项目、尚无产物的单栏对话、资源库、首页、管理后台不出现分隔条。

页面应该直接占满整个视口。不应该在工作台上方再显示营销 Banner、积分条、MCP 按钮或其他和当前创作无关的主工作台头部。

导航面板顶部先是品牌与关闭按钮，紧接着是`素材 / 文案 / 图片 / 视频`资源库四个入口的横排按钮（2026-10-14 用户确认前置到面板最上方，取代此前“固定在项目区下方”的位置）；其后才是“新建项目”和项目搜索，然后展示“最近项目”，默认最多 8 条。项目超过 8 条时在面板内提供“查看全部”，搜索始终覆盖完整项目集合。当前选中项目即使不在最近 8 条中也必须保留在列表上下文里。面板整体高度收窄为固定值而非随内容无限伸展，用户信息区固定在面板底部。

项目行保持单行。列表不展示更新时间，也不常驻展示“可继续编辑”“待完善需求”等普通状态；只有 `生成中 / 待确认 / 需处理`三种有行动价值的状态以同行右侧纯文字显示，不使用胶囊、底色或仅靠颜色表达含义。选中态使用中性浅背景与字重，不使用大面积紫色高亮。

成片浏览态的分镜卡动作常驻可见，不依赖悬停。每张分镜卡提供「说这镜」：点击后对话焦点绑定该镜，输入框预填可编辑的「第 N 镜：」并显示「正在说第 N 镜 ×」，消息被接受、手动清除、切换项目或产物后解除；普通点击分镜卡跳转预览的既有行为不变。存在上一稳定版本且两版分镜可核对时，播放器下方显示「第 N 镜已重做 · 其余 M 镜原样复用」，无可信依据时不显示。修改仍只走对话这一条路径。

## 4. 导航和资源库

导航面板中的“资源库”分组包含四个一级入口，固定在面板最上方：

- `素材`（2026-10-14 用户确认由“资产”改名，全站同步）
- `文案`
- `图片`
- `视频`

资源库是查找与复用已有资源的工具，四个入口在面板顶部横排展示，使用中性浅背景的按钮；每个入口保留明确可访问名称、键盘焦点和当前页状态，不展示数量。

资源库内容页共用同一桌面骨架：顶部显示 `资源库 / 当前库` 面包屑；内容页头左侧显示当前库标题与
用途说明，右侧显示搜索、次级导入动作和唯一主上传动作。分类筛选位于页头下方的独立浅色控制条，
不能与创建动作混成一排胶囊。图片库继续把“内容类型”和“处理状态”显示为两个独立命名分组。

窄屏（≤768px）资源库页头采用可收缩单列：标题与用途说明在上，搜索、导入和上传操作在下并靠左按可用宽度换行。搜索框与所有按钮必须完整位于页头内，不能沿用桌面两列的最小宽度后用外层裁切隐藏溢出；分类筛选仍在独立控制条中。桌面继续采用上述左右两列骨架。

四个库的卡片使用同级圆角、边框、阴影、标题和元信息层级。图片库统一使用 `1:1` 方形预览，
列表居中裁切，详情和下载保留完整原图；视频预览使用 `16:9`，文字卡按内容自然高度。
媒体原始尺寸不得撑高预览框或同排卡片。未配置、加载中、加载失败和空分类均使用
统一状态卡，不回退展示 mock 内容，也不把当前已加载数量冒充资源库总数。

资源详情弹窗统一使用“固定头部 / 独立滚动内容区 / 固定底部操作区”三段结构。头部先展示资源类型与
处理状态，再展示标题和更新时间/引用次数；图片、视频、文案和素材共用该信息层级。媒体预览和正文
只在中间内容区滚动，底部操作不能因长内容消失。

每个详情弹窗只保留一个深色主操作。常用次级操作可直接展示；重新解析、下载、查看来源、导出和删除
等低频管理动作统一收进“更多”菜单。删除保持危险色和二次确认，所有菜单项必须支持键盘访问，不能因
收进菜单而移除能力。已完成视频工程以“打开剪辑器”为主操作，其他资源默认以“用于创作”为主操作。

资源库必须区分“库本身为空”和“搜索/筛选无结果”。只有默认条件下没有任何条目时显示“这个分类还没有
内容”；存在关键词、非默认分类或处理状态筛选时显示“没有找到匹配内容”，并提供一个“清除搜索和筛选”
动作。清除只复位当前库条件，不切换资源库。

分页区只说明客户端已经显示的数量，例如“当前显示 48 项”，不能写成“共 48 项”暗示服务端总数。
存在下一页时使用“加载更多内容”，请求期间改为“正在加载更多…”，失败继续使用可恢复的真实错误提示。
视频详情的浏览与管理可以独立验收；除非用户另行要求，不把“打开剪辑器”作为资源库视觉验收前提。

素材库、文案库、图片库和视频库仍是不同层级的资源入口，导航与数据结构不变：

- `素材库` 承载用户上传、外部采集和对话沉淀的来源资料，后续会接入知识库和检索能力。
- `视频库` 承载主交付物；`文案库`、`图片库` 承载视频生产过程、配套发布和用户明确独立生成后保存的产物。

图片需要作为独立一级图片库，方便封面图、素材图和分镜图沉淀与复用。数字人不是一级资源库，它属于视频的一种表现形式。

导航面板里的项目列表是进入真实历史创作和产物链路的主要入口。项目行要紧凑，规则见第 3 节。重命名、删除等操作放在行内“更多”菜单里。

### 4.1 素材库分类

素材库的一级分类按来源划分，不按“知识库 / 项目资料”这类容易重叠的概念划分。

素材库分类是：

- `上传资料`：对话附件当前支持 PDF、DOCX、PPTX、Excel、纯文本、Markdown、HTML、图片，以及 MP4、MOV、WebM、MKV 视频。YouTube、Bilibili 和公开 MP4 链接可以直接粘贴到输入框；音频可以作为生成产物展示，但当前不是本地上传类型。
- `采集资料`：从外部链接或平台采集来的内容，例如网页、公众号文章、视频链接、行业报告链接和竞品页面。
- `对话沉淀`：用户明确要求保存为资料的对话内容或资料整理结果。跨项目的主题、受众、表达偏好和长期约束进入独立“创作档案”，不再作为偏好型 ContentAsset 放进素材库。

素材库不显示“用途标签”。内容类型、解析状态、检索关键词和向量索引状态可以保留在数据层和详情层，但不要在列表里堆叠成多个可见分类标签。

来源分类只消费后端显式 `source_type`。字段缺失或值未知时显示 `未分类`；前端不得从标题、正文、文件名、链接或引用地址推断来源类别。

素材库列表应该优先展示：

- 标题
- 来源分类
- 内容类型
- 处理状态
- 更新时间

素材详情可以展示：

- 内容摘要
- 原始来源或文件信息
- LLM 提取的检索关键词
- 解析、切片、索引状态
- 最近被哪些创作引用过

知识库是底层能力，不作为用户可见的一级分类。用户看到的是资料从哪里来、是否已可检索、能不能用于创作。

### 4.2 产物库分类

文案库、图片库和视频库只显示已经确认的产物分类，不再显示旧的类型、版本、状态或关键词标签，避免列表看起来像有多套分类体系。

文案库分类是：

- `选题方案`
- `文案稿`
- `编导稿`

图片库分类是：

- `封面图`
- `素材图`
- `分镜图`

视频库只使用一个正式分类：`视频工程`。讲解、真人原视频、原片摘编、讲解型中的过程表达、MG、实拍或生成画面都是同一视频工程内部的内容骨架或制作方式，不再成为并列产品分类。

视频库只收录服务端对外状态为 `completed` 的视频工程。失败、生成中的工程保留在原项目供查看原因、恢复与重试，不能进入库列表或库内搜索；不得为隐藏失败而删除历史记录。上传原视频仍可在库中复用，素材理解失败与视频制作失败分别处理。

编导稿与口播稿按文字类型读取，不能混入视频网格；普通列表与关键词/语义搜索共用此类型边界。历史稿件仍可在原项目中读取，不因展示分类而改写或删除。

视频卡片展示已有真实封面；缺封面的历史视频进入视口后只读提取真实视频帧，解码并发最多两个，完成、失败、取消或超时后释放媒体，不写数据库或调用生成模型。原视频或封面不可读时显示明确的不可用状态，不以统一“视频预览”图案或无关图片充当封面。

公共导入视频的供应商 `preview_url` 用于封面，播放优先使用已保存原视频、其次为直连视频地址；没有视频地址时不能把封面图片或来源网页交给播放器。

产物分类只消费后端显式 `artifact_category` 或已约定的结构化 `content_type`。字段缺失或值未知时显示 `未分类`；前端不得从标题或正文关键词猜测产物类别，也不得为缺失的检索标签补固定词表。

产物列表卡片只显示一个正式分类。标题只保留主题本身，不再把“草稿”“视频文案草稿”“编导稿”等阶段词拼进标题。第二行只显示“正式分类 + 轻状态”，例如“编导稿 · 有来源”。检索关键词可以放在详情弹窗里，供后续搜索和引用，不作为列表标签展示。

图片库工具栏必须把“内容类型”和“处理状态”呈现为两个带可访问名称的独立筛选组。
`封面图 / 素材图 / 分镜图` 属于内容类型；`已解析 / 待处理` 属于处理状态。两组可以组合
生效，但不得只靠分隔线、小圆点或同款胶囊让用户自行猜测维度。

用户只粘贴一段长文案或资料时，系统先把它当作待处理素材，并围绕短视频主线询问用户想做的视频主题或用途；如果用户明确要“优化文稿”“提炼封面图文”或“保存为素材”，则尊重该独立产物意图。只有目标已经明确时才进入对应生成链路。

点击文案、图片或视频库条目时，详情以居中模态弹窗打开（2026-07-08 规范 §10 决策，覆盖旧详情形态约定）；工作台产物详情仍为顶部「详情」浮层。视频工程详情统一展示编导、分镜、素材、音频、字幕和导出信息，具体内容按可用能力呈现。

### 4.3 资源库条目管理

素材库、文案库、图片库和视频库的条目详情里统一提供基础管理动作，不按库单独设计一套规则。

- `下载`：优先下载用户上传、公开导入或系统保存的原始文件；如果该条目没有原始文件，则下载包含标题、正文和来源引用的 Markdown。
- `删除`：采用软删除/归档语义。删除后该条目从当前库列表、库内搜索和语义搜索中隐藏，但不物理删除底层文件，避免破坏历史对话、来源引用和已生成产物链路。
- 归档成功后关闭详情、刷新当前库，并保持原来的素材/文案/图片/视频库视图，显示“已删除”反馈。项目资料或摘要的后台刷新不得自动切回项目对话、卸载当前库或抹掉成功提示；用户主动选择项目时才切换。归档已完成但项目资料同步失败时，保留成功事实并提示重新加载项目，不将其误报为删除失败。
- 删除前必须有二次确认，确认文案应明确“删除后将从当前库隐藏”。
- 真实后端已连接时，库列表以真实后端返回为准；真实库为空时不要回退展示 mock 示例，避免用户误以为删除失败。
- 这些动作放在详情（模态弹窗）的操作区，不放在列表卡片上，保持列表浏览密度。

## 5. 对话规则

### 5.0 新建视频项目首入口

- 新建页继续以大对话框作为第一操作入口。开始方式卡必须位于对话框下方，避免让用户误以为需要先选类型，也避免在窄屏把输入入口推到首屏之外。
- 登录和新建页主提示统一为「说出想法，让 AI 帮你更快、更省力地做出短视频。」输入示例从创作目标开始，不预设用户已经上传素材。
- 新建页、内容区和输入栏的网格列必须能缩到可用宽度；窄屏输入内容、发送按钮、开始方式卡和案例卡不得横向被裁掉。能力提示可以在自身列表内横向滚动，不得撑大整个页面。
- 对话框下方先显示一行被动能力提示：`我的素材 / AI 生成镜头 / 图形动画 / 原视频优化 / 配音与音乐`。它们只说明系统可按镜头组合这些能力，不是筛选器、技术选项或强制步骤；普通用户界面不显示 H3、HyperFrames、Remotion 等内部名称。
- `你想怎么开始？`展示三张紧凑入口卡：`从想法开始`（说出目标，一起确定内容和画面）/ `用素材创作`（上传照片、人物、资料或参考片，制作新作品）/ `修改现有视频`（上传原片，说明要保留和调整的部分）。卡片使用清晰背景图和深色可读性遮罩，不放图标；桌面三列，窄屏两列且第三张跨整行，移动端单列。输入框保留单条可编辑示例，不在卡片下方重复展示三种输入条件。
- 入口下方的`看看能做出什么`展示最多三条经确认的 MultiMix 真实成片案例，可以只上架一两条。卡片先给可播放成片的封面、入口类型、用户提供了什么、最终做成什么；点击后在详情中播放成片，并展示真实发生的“需求 → 方案 → 修改 → 成片”关键步骤。仅有修改前原片也获公开授权时，展示原片与成片对比；视频不得自动播放或裁切主体。完整聊天记录不直接铺在首页。
- 案例上架须有产品原生完成记录、完整观看后的质量结论，以及成片、原素材、人物、音乐和品牌的首页公开展示授权；过程摘要须与真实记录一致。现有内部 QA 成片不具备公开发布状态，不得冒充首页案例；在没有合格案例时隐藏整个案例区，不显示空卡、占位视频或“即将上线”。当前原型中的卡片必须显著标为结构示意。
- 参考片用于制作新作品时归入`用素材创作`；需要保留现有原片并作调整时归入`修改现有视频`。人物出镜、口型、参考片复刻或活动大屏等具体要求均可在输入框提出，但入口不承诺其当前均能稳定交付。
- 点击开始方式卡只把明确、可继续修改的意图写入输入框，不伪造用户已上传素材、不自动提交，也不跳过比例、时长、配音或原视频处理确认。开始方式卡不预选，只有用户实际点击后才显示选中态；案例详情不会替用户自动发起制作。
- 桌面首屏适当收紧空输入坞高度；“这些会限制制作方式吗？”应靠近能力提示，明确入口只是起点，避免与下方开始方式卡形成脱节的第二套说明。
- 工作台使用统一的系统中英文字体栈；正文不小于 14px、元信息不小于 12px，常规字重收敛为 400/500/600，正文和次要文字保持可读对比度。抽屉打开时背景变暗是遮罩行为，不用字体样式掩盖这一状态。
- 新建页不展示“你的素材可以开始做视频了”或其他只统计图片却泛称全部素材的就绪横条。
  只有服务端未来提供图片、视频和资料的统一可用性汇总时，才重新设计跨素材类型入口；当前
  不为该提示额外请求图片库，也不用图片专属文案替代。
- UGC 属于表达风格，可以用于真人、物品、过程或故事，不单独显示为顶层视频类型。真实素材、生成视频与图形动画可以出现在同一作品中，具体制作方式由编导和逐镜计划决定。
- 后端按 `任务类型 → 内容目的 → 表达风格 → 制作模式 → 逐镜执行` 五层组织创作决策。普通用户看到的是“四维创作画像 + 逐镜执行方案”：前四维是作品目标与整体制作偏好，第五层是每镜实际执行方式，不是另一个分类。前端通过同一个对话入口收集并展示服务端结果，不把五层改造成五步必选向导。`explainer / presenter` 不进入新系统；切换时清理旧对话及旧工程状态，前端不提供旧项目兼容入口。
- 提交后的确认信息用用户语言展示内容目标、风格、预计分镜数、素材/生成/动画组成、耗时与费用；不要求用户选择模型或渲染器。
- 当前对话底层就是该视频项目的连续工作区：后续补充的素材、文案、封面和视频版本都围绕同一当前作品组织。用户界面的首入口、列表和管理动作统一使用“项目”；输入区仍是项目中的对话方式，不做内部模型和 API 的机械重命名。
- 仅当项目已有资源时，在对话头部显示紧凑的「资料 · 数量」入口；常规宽度位于标题右侧，窄屏（≤520px）与诊断操作一起放在标题下方、同一头部内右对齐，以保留可辨认的项目名。空项目不显示资源入口，也不增加独立横条。点击后打开轻量抽屉，按需分页加载，不新增工作区一级 Tab。抽屉在极窄屏（≤380px）将素材名称与状态放在操作按钮上方，不能为保留同行操作而把名称挤到无法辨认。
- 对话详情读取失败时，已保存项目的资料摘要仍独立读取；有资料且摘要成功时保留入口及分页抽屉，允许查看素材和现有受控管理动作，不因此开放需要完整对话的创作写入。资料摘要本身失败时不猜测数量；文案、封面和视频产物若因对话详情缺失而不可定位，提示先重试加载对话。
- 素材分为“当前使用”和“历史资料”。移出项目只影响今后的生成，不改变旧文案、旧封面、旧视频和既有分镜；源文件仍可用时重新加入，才恢复为未来上下文。全局资源库归档已关联项目的素材时，项目成员关系不伪装成“已移出”，但素材从未来上下文移至历史资料并标为“已归档”；恢复源文件后可重新成为当前素材。已归档或尚未就绪的历史素材保留旧版本引用及查看入口，不显示无法完成的“重新加入项目”操作；状态未知时也不猜测可用性。归档详情仅查看，不显示新创作、加入项目、重新解析、重试、下载或删除等后端会拒绝的操作；未完成的理解/解析状态只能表述为归档前事实，不继续显示等待中、处理中或可检索。文案、封面和视频在项目资源中只查看，不提供项目级删除。
- 新素材通过对话输入区带入项目；从全局资源库点击“加入项目…”时必须显式选择目标项目，禁止默认使用上次项目或另一个标签页里的项目。没有项目时引导“新建项目”，但不静默创建空项目。
- 「项目资源」只显示用户主动带入或已被当前项目产物实际引用的资源；不把搜索候选或未使用素材自动计入。资源库用于查找、复用和管理已有资源，而不是新建视频的首要入口。
- “素材角色”和“使用方式”仍是服务端需求快照里的项目级上下文，前端不根据文件名或文字词表推断；实际分镜使用仍以 `asset_reference` 为权威。这些理解不在项目资源抽屉里只读展示，也不形成角色/策略下拉框。
- 项目资源抽屉只承载打开、移出与可用历史资料的重新加入，不重复提供上传入口。项目关系及历史引用会阻止源文件永久删除，因此抽屉不展示必然失败的“永久删除源文件”；后端引用保护不放松。抽屉只显示有内容的资料类型，每次打开或切换项目都从当前可用资料首屏开始；仅有历史资料时默认显示历史资料。当前/历史数量变化后自动切回仍有内容的范围；汇总变化触发列表刷新，页码以列表总数校正，不得因短暂汇总差异漏页或误报“没有资料”。历史资料作为次级查看入口。Agent 对素材角色、用途和冲突的判断与纠正都留在原对话中。
- 上传单个或批量 PDF、DOCX、PPTX、表格和文本后，Agent 在现有消息流中用普通助手回复说明“我理解的是……”。它可以简短列出目标、受众、交付物和必要来源，但不渲染独立需求卡、完整需求表单或字段维护区。上传、解析和理解本身不开始视频或付费生成。
- 阻塞冲突由 Agent 在普通助手回复中聚焦指出并展示必要的可追溯来源，然后请用户直接在原输入框自然语言回复。上传文件证据在正文中写出文件标题、证据位置和原文；截图或图片证据直接在同一回复中显示实际图片，并在图旁显示证据位置和原文，禁止只显示图片名。普通界面不提供冲突选项按钮、“使用我填写的内容”输入项、弹窗或独立确认窗口。
- 用户回复的语义由后端模型结合当前完整需求快照、冲突候选、证据和对话上下文结构化判断；前端不猜选择，后端 Python 也不使用词表、正则或字符相似度路由。含糊回复由 Agent 继续追问，未解决阻塞冲突继续阻止生成。
- “基于当前需求新建项目”复制最后确认快照与当前有效素材关系，不复制聊天、产物或任务。克隆项目显示持久化的继承提示，即使刷新页面仍说明其为独立项目、聊天与产物从空白开始。

对话是理解短视频需求并判断以下内容的主要位置：

- 产物类型
- 发布渠道
- 目标受众
- 内容格式
- 画面比例
- 时长
- 风格
- 语言
- 默认生成什么短视频，以及编导、封面、分镜、音频、MG、实景或数字人讲解等配套产物和制作方式；用户明确只要文案或图片时保留独立生成路径

当对话已经理解用户要生成什么以后，展示区不应该再要求用户选择一级 `文案 / 图片 / 视频 / 音频 / 数字人` Tab。

产物生成完成后，助手回复应该简短说明：

- 生成了什么
- 基于什么内容生成
- 用户接下来可以怎么调整

推荐的自然语言调整建议示例：

- `缩短到30秒`
- `换成9:16`
- `把第2段素材换成产品图`
- `改成数字人讲解`
- `字幕更大一点`
- `生成一份4:5封面方案`

下一步推荐操作优先放在助手回复里，不要在展示区再做一套独立推荐模块。

### 5.1 Agent 任务、确认与执行反馈

- 对话视觉应按“用户目标 → AI 编导判断 → 当前方案/产物 → 真实执行状态 → 下一步”组织；AI 回复使用稳定的轻量身份标识，不能把任务卡、确认卡与普通正文伪装成同一种聊天气泡。
- 展示区继续服务于当前结果，对话轨继续服务于提出目标、解释判断、确认风险/费用和继续局部修改；导航面板继续承载项目与资源导航，不新增独立 Agent 控制面板。
- 对话仍只有一个面向用户的 Agent。用户可以中途问问题或开始另一项创作；只读插问不替换当前
  任务，新任务会暂停旧任务并允许稍后返回。
- 用户对当前可编辑产物提出具体修改，即使使用“可以……吗”之类礼貌问法，也按修订意图处理并保留当前作品上下文；只询问能力、原因或状态时保持只读，不启动修改或生成。意图无法可靠判断时应明确说明，不能猜测执行。具体路由与确认边界以[对话编排权威规则](../../MultiMix-Backend/docs/authority/conversation-orchestration-rules.md)为准。
- 用户只有模糊目标时，助手先给一个带明确假设的推荐方向，只追问最影响下一步的一项信息。询问安排理由或改进建议保持只读；建议绑定当前作品版本，用户明确采纳后才进入修改权限和费用校验。
- 当后端返回有效 `agent_mission.agent_v2` 时，对话标题下方显示轻量任务条：`当前：<目标>`、
  暂停任务数量，以及一个返回栈顶任务的入口。界面不显示 task ID、action ID、内部状态码或
  Production Stage 名称。
- Agent 修改需要确认时复用现有确认卡；卡片显示用户能理解的修改内容和范围。确认 ID 只在数据层
  传递，不展示给用户。
- 视频方案、视频制作和视频修改使用统一的紧凑进度卡：详情默认收起，用户展开后只展示已发生且已登记的公开阶段，不按固定数量截断；完成后回到简短状态摘要。失败不强制展开，但失败原因和必要操作始终可见；独立图片、文案、上传和导出继续使用原进度展示。没有服务端可靠数据时，不显示进度百分比、预计完成时间或虚构阶段。
- 视频进度不显示步骤序号、总步骤数、逐步耗时、Provider、模型或内部修复事件。未知内部事件合并进当前
  产品阶段，不把原始标签直接展示给用户。只有服务端完成判定对账后才显示“视频已做好/已更新”。
- 首次生成失败时，展示区只显示失败原因与可执行恢复动作，不显示旧编导时间轴；已有稳定成片的局部操作失败继续显示上一稳定版本，并单独说明本次失败。
- 页面刷新或切换对话后从持久化任务恢复并默认收起。已确认进入后台的任务提示用户可以离开当前对话；
  读取失败显示“暂时无法更新进度”并保留最近真实阶段，恢复轮询同一个任务。
- 失败只在服务端明确允许时显示重试。异步修改失败时，展示区继续展示上一份稳定视频工程。
- 资源库中的可用素材从详情页“加入项目…”后立即持久化；它只改变项目今后的素材上下文，不立即修改编导稿、分镜或视频。项目内重新明确附件一个历史素材时，视为用户主动重新加入。

### 5.2 五层规划与单一推荐

- 生成编导稿前的第一确认卡同时确认比例、时长和 AI 配音。服务端先冻结唯一 `video_parameters`：用户明确比例优先，其次采用权威主要上传视频原始比例；纯文字、图片、PDF 或没有主要视频时默认 `16:9`。多视频比例冲突且没有主要视频时必须由用户选择。
- 服务端根据对话和素材形成 `任务类型 → 内容目的 → 表达风格 → 制作模式 → 逐镜执行` 的当前推荐方案，不再要求或返回讲解型/真人原视频型。操作、过程、前后变化、原片删留、MG overlay 和图生视频都进入对应层级与分镜执行，不成为独立入口。
- 用户始终可以改比例。改后媒体画布保持主体完整，默认 contain/留边，禁止为了适配新比例静默中心裁切人物、产品或关键信息。
- 声音优先级为用户明确选择 > 有效说话内容保留原声且 AI 配音默认关闭 > 从头生成或无可用说话内容时 AI 旁白默认开启。旁白文字和是否合成语音分开；关闭配音不删除文字。
- TTS 不可用不能改变产品默认。需要 AI 旁白时确认卡明确提示，并允许用户关闭配音继续；在选择有效前不得出现草稿、工程或“已完成”。
- 编导稿由模型根据主题、五层方案、素材和事实边界自主产生 1–5 个真实差异的创意方向，推荐项自动进入分镜规划，不增加开始前确认门。创意方向显示在生成该编导稿的助手消息、产物卡之后；默认只显示当前采用项，用户主动点击“查看其他方向”才展开本轮已有候选。浏览不修改编导稿，只有点击“应用此方向”才用候选 ID 与候选集 fingerprint 排队修订同一编导稿。展示区只显示当前编导稿或视频结果，不重复显示方向选择器。不得设置固定候选数、固定行业模板或按前端关键词拼方向。
- 当第四层要求保留真人母轨和原声时，默认只展示服务端胜出的一个推荐方案和一个样片；用户明确“换个方向/再生成一版”后才请求并显示下一版。其他组合沿用同一版本、撤销和恢复机制，不分两条流程。
- 需要真人原片清理时保留对应的第二道确认，但语义是确认当前来源删留和制作方案。用户修改已有说话内容时，必须明确选择只改屏幕文字、生成 AI 配音或重新上传录音，不能把字幕修改静默变成声音修改。
- 参数确认卡始终显示用户当前选中的比例、时长和配音状态；关闭配音后旧的“开启（默认）”摘要必须立即消失。服务端确认返回后再以冻结快照为准。视频任务进度不显示阶段耗时；其他任务原有计时规则保持不变。
- 参数确认前，创作画像是可以随新脚本、新素材和自然语言修正重新评估的提案；确认后才冻结。视频方案确认卡首层依次展示内容方向、计划构成、交付格式/时长和素材影响；模型已给出自由文本方向时，它优先作为“内容方向”，结构化画像仅作为可展开的制作偏好。完整配乐候选与试听收进“查看制作细节与预览”；计划构成只描述当前逐镜方案，不能暗示素材已经采用或镜头已经完成。作品执行后的实际构成以服务端返回的当前工程与分镜事实为准。
- 没有上传素材时 `anchor_source=null` 是合法方案，前端不得因此隐藏或拒绝确认卡。一般原片保留原声与真人连续母轨是两种不同方案；前端只展示后端投影，不根据文件名、文案或素材类型自行改写为真人原视频。
- 没有可执行视觉素材时，现有参数卡最多展示三个服务端当前可执行的制作方式，说明效果、必要输入和费用；推荐项不能替代用户选择，改变选择须更新同一服务端方案。
- 已保存素材的匹配结果与最终采用的主画面是两件事实：命中不能因推荐其他画面而被改写为“未命中”，也不能把“已命中”展示为“已用于成片”。素材优先级、逐镜引用与确认后的来源选择以[素材理解与分镜引用权威规则](../../MultiMix-Backend/docs/authority/asset-understanding-and-segment-referencing.md)为准。

### 5.3 创作档案与视频完成后的记忆确认

“创作记忆”是跨项目复用的底层能力，“创作档案”是用户查看和管理它的入口。它同时服务个人创作者与商家/品牌主体，不使用“商家记忆”或“记忆卡”作为通用产品名称。

第一版采用一个账户一个主要创作主体、一个默认创作档案：

- 不要求用户选择“个人 / 商家”，也不在 onboarding 中强制填写档案。
- 账户区域增加“创作档案”入口，不新增左侧一级导航。面板提供简短隐私说明和完成后提醒偏好，不新增重型设置页。
- 空档案先解释“完成视频后，MultiMix 会把可能长期有用的偏好交给你确认”；手动添加是次要入口，不展示五组空白重表单。
- 有内容时按“关于你或你的品牌、内容与受众、表达偏好、必须遵守、希望避免”五组展示，支持单项编辑/删除、整体清空和暂停使用；另设“已忽略建议”入口，允许查看、恢复和清空明确抑制的内容。
- 名称、简介和已确认事实第一版只允许手动维护；系统不从聊天或素材中自动写入事实。
- 新视频默认使用已启用档案。当前项目提供“本项目不使用创作档案”，用于临时替他人或替其他品牌创作；它只影响当前项目，不是隐式多档案。创作区显示“本次使用创作档案 · N 项”，展开后只展示当前项目冻结采用的条目，不用账户档案的最新状态冒充本项目已经采用的内容。

创作档案只在新视频开始时读取一次。界面展示当前所选视频冻结采用的档案状态；档案后续修改不追溯改变已有编导稿、分镜、视频工程或导出，旧作品的普通修订仍沿用原快照。第一版不提供旧作品按最新档案重新规划入口。当前项目的明确要求始终高于已保存档案。

完成后确认采用以下确定性交互：

- 前端只消费后端对外 productStatus=completed；这表示所有发布必需的素材、画面、字幕和已规划动效已经完成，视频可播放、编辑和导出。
- job.status=completed、内部 video_project_ready、生成进度文案、用户说“可以/满意/以后都这样”以及导出动作都不能触发确认。
- 对外状态变为 completed 后，前端查询当前项目素材绑定的候选批次。queued/running 时只做有上限的轻量轮询；ready、候选已通过后端置信度/新颖性/隐私审核且用户提醒偏好允许时才展示。
- 确认卡位于当前视频工程结果内容末尾，不覆盖播放器、不使用模态弹窗，也不阻止用户继续播放、编辑或导出。
- 每个稳定完成的视频版本最多展示一次，最多 3 项。每项显示简短候选内容与形成原因，默认允许逐项选择。
- 只有点击“保存 N 项”并由服务端成功确认，选中项才跨项目生效。“不要再建议”抑制同一项，但用户可在“已忽略建议”中恢复；“这次先不处理”只关闭当前视频版本。
- 连续两次选择“这次先不处理”后，确认卡只提供一次“降低提醒频率 / 关闭提醒”设置，不自动替用户改变偏好；降低频率后默认 30 天内不再提示。
- 删除已保存条目默认只执行“仅删除”。如需同时抑制未来建议，必须明确选择“删除且不再建议”；两种操作不得合并成无说明的单一删除按钮。
- “仅用于本项目 / 以后创作也使用”只能作为结构化控件的字段值；前端不得解析自然语言同义表达来替用户选择。
- 没有候选、候选提炼失败、批次过期或服务端返回终态失败时不显示空卡或错误提示，视频完成状态及操作保持不变。
- 刷新、断连恢复、重复 worker 事件、重试和导出不能重复创建或重复展示同一完成版本；前端以服务端候选批次和状态为准，不在本地猜测去重。

这张卡是“是否保存跨项目偏好”的专用确认，不复用整份编导稿确认卡。它可以复用现有按钮、勾选、弹层样式和错误反馈原语，但必须支持部分保存、明确拒绝和只关闭本次三种不同语义。

第一版只有视频链路会消费创作档案并在完成后产生候选。文案和图片可以继续作为独立产物生成，但不读取档案、不自动提炼候选，也不展示这张确认卡。

发布按 `off -> shadow -> 商家优先小流量完整闭环 -> 扩量` 推进。shadow 阶段无用户可见入口；外部用户只有在候选展示与下一次视频规划消费同时命中同一灰度资格时才看到自动候选和“已保存”反馈，不允许出现界面承诺已经记住、下一次却静默不使用的虚假闭环。产品能力仍兼容个人用户，但首轮访谈和 go/no-go 以商家用户为主，指标按用户类型分群。

真实 shadow 测评暂不作为本地开发收口条件，但仍是对外灰度前的质量门槛。没有获授权的真实候选评测和生产权限核对时，保持候选模式 `off`、外部用户名单为空；隔离 E2E 中的模拟候选不能被解释为已具备真实用户发布资格。

## 6. 产物卡和产物切换

当一个对话生成多个产物时，每个产物都应该以产物卡的形式出现在对话流里。

点击产物卡，展示区切换到对应产物。

项目名只负责导航面板和对话头部的导航上下文。对话产物卡与展示区头部负责说明当前产物身份，
统一显示“明确产物类型 + 版本 + 状态”，例如 `封面图 · v1`、`编导稿 · v2`、
`视频工程 · v1`，不再机械重复完整项目名。产物类型按后端显式 `artifact_category`、约定的
`content_type`、最后才是通用 `mode` 标签的顺序确定；禁止根据标题或正文关键词猜测。
完整原标题仍保留在详情和下载命名中。

对话产物卡必须使用消息区的明确可用宽度，桌面最大宽度为 `560px`，不能因父级收缩上下文
把百分比宽度再次压缩成窄卡。

图片和视频产物卡优先显示已有的真实生成预览或代表帧，便于用户在对话历史中快速辨认结果；没有可用预览、预览加载失败或文本类产物时，回退正式类型图标。前端不得为卡片伪造缩略图或触发额外生成。

展示区只显示当前选中的产物。上下游关系可以通过以下方式表达：

- 对话中产物卡的出现顺序
- 产物的简短元信息
- `详情` 抽屉

不要为了切换产物，在展示区再增加强制性的产物 Tab。

## 7. 展示区设计原则

展示区是单一的当前产物工作区。

它应该优先做到：

- 完整展示结果
- 预览不被遮挡
- 图片和视频类产物居中展示
- 减少不必要的 UI 装饰
- 保留轻量标题和状态
- 只在需要时显示 `详情`、`复制`、`保存` 等操作

桌面组件采用三档操作高度：产物头部紧凑工具栏为 `30px`，普通筛选和次级操作为 `36px`，
上传、发送、确认与恢复等主要操作为 `40px`。正文不小于 `14px`，按钮标签不小于
`12.5px`，需要阅读的状态、版本和说明不小于 `12px`；`--sp-faint` 只用于装饰性信息，
不能承载必须阅读的元数据。

它应该避免：

- 大面积配置面板
- 围绕结果的大块可见边框
- 重复的推荐操作区域
- 默认展示产物结构卡片
- 来源证据和参数信息占据主区域
- 强制用户切换画布、分镜、时间轴、素材、参数等工作视图 Tab

## 8. 不同产物的展示规则

### 8.1 文案产物

文案产物包括：

- 选题方案
- 文案稿
- 编导稿

视频文字方案统一归入 `编导稿`。用户只要旁白文字时，允许生成不含完整分镜的轻量编导稿；配音属于声音制作能力，不作为另一类文稿。

系统主动展示的视频文字方案名称统一使用“编导稿”，覆盖分类、产物卡、操作、状态和错误提示；用户原话与历史稿件正文保持原样。

处理后的素材包也是产物，不是原始素材。它属于基于来源素材二次加工后的文案产物。

文案产物应该在展示区完整展示，方便用户阅读、复制、保存和后续复用。

在默认短视频流程中，文案产物主要承担选题、编导、屏幕文案和旁白等生产角色；用户明确只要文案时，仍允许独立交付。

默认视图不应该是产物结构面板。如果结构、来源、参数或版本信息有价值，应该放进 `详情`。

### 8.2 图片产物

图片产物包括：

- 封面图
- 素材图
- 分镜图

图片预览应该在展示区居中显示。可见边框要尽量少。主区域应该让用户看到图片结果，而不是看到配置表单。

桌面图片结果使用显式 `minmax(0, 1fr)` 网格轨道并从顶部开始排布，主图占据结果区的合理
内容宽度；允许在超宽屏设置结果类型自己的最大宽度，但不得回退为大面积空白中的收缩小卡。

在默认短视频流程中，图片产物主要承担封面、素材补充和分镜画面等生产角色；用户明确只要图片时，仍允许独立交付。

比例、数量、风格、参考素材等轻量控制可以在必要时出现，但大部分调整应该通过自然语言完成。

### 8.3 视频产物

视频产物统一为 `视频工程`，工程导出就是最终视频，不再建立“工程 / 成片”双产品。MP4 是否已经导出、工程是否可编辑和某次局部操作是否成功，均不增加第四种产品状态。

默认展示应该让视频预览居中。只有当时间轴能帮助用户理解或检查结果时，才在主视图里显示紧凑时间轴。

视频工程浏览态允许在单个分镜卡片上提供“换素材”和“修改配音”两类轻量动作。两项操作默认隐藏，只在卡片悬停或键盘焦点进入时显示；当前选中分镜不常驻显示操作按钮。点击“修改配音”打开居中模态窗口，复用胶片条现有配音编辑器，支持试听后应用；它不把裁剪、分割、排序或完整时间线控制搬进浏览态。“应用到全部分镜”必须再次确认，任务运行期间窗口不可关闭，成功后刷新同一视频工程。分镜标题只显示数量，不再附加“点击任意分镜可跳转成片/切换预览”等说明；卡片本身仍可点击定位。

同一视频产物有可播放的上一稳定版本时，浏览态提供“单视频 / 版本对比”：单视频用于制作和浏览全部分镜，对比模式并排展示修改前后两条完整成片，只列受影响分镜供用户复核。没有历史完整成片时不展示空对比；当前版本已经保存，无需再次采用。详细的差异证据、声音、焦点、失败状态及矮屏交互统一见[编导稿与视频工程展示状态](specs/ui/video-artifact-browse-and-edit-states.md#成片版本对比模式)。两个播放器均遵守下方 `video-preview-shell-contract:v1`。

浏览态如需在主区保留素材来源摘要，必须默认收起，仅显示“基于多少素材生成”的标题；用户点击后再展开素材条目和命中说明，完整来源信息仍放在「详情」。分镜滚动区必须为卡片阴影预留绘制空间，禁止在滚动边界把阴影直接裁断。

视频预览必须区分“播放器外壳”和“媒体画布”：

- 播放器外壳使用白底、`1px solid #eae7e1`、`20px` 圆角、`7px` 内边距，以及 `0 2px 6px rgba(32, 31, 30, 0.05), 0 16px 40px rgba(32, 31, 30, 0.07)` 阴影。
- 媒体画布内部可以是黑底、无边框，并按真实素材保持 `9 / 16` 或 `16 / 9`；“媒体画布无边框”不等于“播放器外壳无边框”。
- `9 / 16` 或 `16 / 9` 只约束媒体画布，不约束“媒体画布 + 底部控制条”的整个播放器外壳；控制条必须在画布下方自然增高，禁止挤压或变形媒体画面。
- 浏览态播放器按内容自然占高，后面直接衔接分镜摘要；禁止用固定高度预览容器或独立纵向拖拽条制造播放器下方空白。
- 用户已于 2026-08-05 批准：浏览态外层保持自然滚动（不回退为 `overflow: hidden`），为分镜卡阴影保留绘制空间；播放器容器保持当前 `0 0 20px` 间距，不恢复原型历史的 `4px 0 0` 间距。
- 默认浏览态只服务于观看：嵌入式预览不得显示缩放、构图网格或编辑器全屏工具；用户主动点「编辑」后才显示这些专业调整工具。播放器画面内保留播放与进度控制。
- 分镜轻量预览是每镜的“视觉起始状态”，不是缩小版成片：有主素材时展示该镜的主素材或可识别代表帧，让用户知道这一镜从什么画面开始；不使用素材的动画、图形或品牌收束镜，必须展示与该镜 `visual_treatment` 一致的背景、版式或静态起始态。它不需要复刻完整字幕、MG overlay、配音或最终合成动效，但不得因“无主素材”退化为空白画布或伪装成素材缺失。
- 只有素材确实待补、加载失败或工程状态无法确定时，轻量预览才显示明确的占位/失败说明；“图形主画面”是正常可预览状态，不能使用“待补素材”文案。
- 素材缺口提醒必须依据当前分镜或工程的真实状态，说明哪些画面仍待补或无法确认，以及用户下一步可做什么；已有可用主画面时不显示缺口。只有字幕或标题卡确实进入当前画面时，才能声称它们已代替缺失素材。
- 预览准备、播放失败等状态只在播放器画面内用用户语言短暂说明，不在播放器下方重复显示“完整工程”等内部制作术语。背景音乐和正常素材来源放入「详情」；只有用户需要处理的素材缺口才在主区显示提醒。
- 工程预览加载失败时，保留白色播放器外壳和分镜卡，画布内显示“预览暂时无法加载，可先查看分镜”及“重新加载预览”；重试必须重新挂载预览 iframe，不显示“完整工程”等内部术语。
- 用户已于 2026-08-04 批准：首帧/缓冲准备期间，白色媒体画布内显示“正在加载视频 · 已缓冲 N%”和真实缓冲进度；中央播放键、进度条与分镜跳转必须禁用，直到浏览器确认可播放。未知总量时使用不确定进度，不得伪造百分比。
- 已有成片播放器与无成片的分镜预览必须共享同一套白色细边框、圆角和柔和阴影外壳；待补素材、首帧未加载和失败提示的默认画布使用白色，只有真实图片或视频加载后才显示其实际画面。
- 底部控制区只保留当前时间、轻量进度条和总时长；播放/暂停由画面中央按钮承担。
- 中央播放按钮固定为 `44px × 44px`，内部播放图标为 `16px`，使用半透明白底和 `0 6px 18px rgba(0,0,0,.25)` 阴影，画面悬停时缩放到 `1.07`。

### 8.3.1 生成与失败状态的动作归属

- 当对话执行时间线存在服务端提供的真实 `retryJobId` 时，时间线拥有全页唯一的主要恢复动作；
  展示区只显示失败摘要和“在对话轨重试失败步骤”的范围说明。
- 只有对话侧没有可用恢复动作、且服务端显式给出 `modify_script`、`replace_scene_asset` 或
  `retry_scene_generation` 时，展示区才显示一个与该动作一致的主要按钮。`replace_scene_asset`（失败后重新寻找该镜素材）已随公共素材于 2026-10-16 退役，历史失败改为 `modify_script`。
- 不可重试时只显示原因和下一步说明，不生成看似可用的通用重试按钮。
- 生成中和失败时隐藏保存、编辑和导出；只有稳定完成的产物才显示对应操作。

### 8.4 数字人讲解视频

数字人是视频的一种表现形式。

它不应该被当作展示区里的一级产物类型。

默认展示方式：

- 中间展示当前数字人讲解视频预览
- 下方在必要时展示逐句音频/字幕时间轴
- 不在预览区显示来源证据卡

数字人讲解视频只需要知道它使用的是哪一版文案或旁白文字。来源证据、生成链路、人设、字幕设置、渲染信息等都放进 `详情`。

如果需要显示旁白文字，默认应该折叠或紧凑展示，避免占用过多视频预览空间。

### 8.5 音频和字幕匹配

音频和字幕匹配通常属于视频生产的一部分，不需要单独成为主场景。

它可以表现为：

- 视频下方的紧凑时间轴
- 逐句时间块
- 字幕匹配状态

如果用户专门处理音频产物，也可以使用同一套模式展示波形和逐句时间，但仍然要避免重边框和复杂配置感。

真人原视频的画面、原声、字幕、图文和音乐读取同一播放映射；原文字幕中的长英文 cue 按画布测量换行，不得溢出媒体画布。

## 9. 详情（产物浮层 / 库详情弹窗）

`详情` 是承载有价值但不应该占据主展示区的信息的地方。

工作台产物的详情以顶部「详情」浮层打开，不挤压主预览区域；库条目的详情用居中模态弹窗（2026-07-08 规范 §10）。

详情可以包含：

- 生成依据
- 来源链路
- 来源映射
- 素材分配
- 产物参数
- 画面比例
- 时长
- 风格
- 人设
- 字幕设置
- 声音和字幕匹配
- 渲染状态
- 版本信息
- 上下游产物关系

详情回答的是“这个产物为什么这样生成、怎么生成的”。主展示区回答的是“我得到了什么结果”。

## 10. 输入框和调整方式

输入框应该有 AI 原生产品的感觉：

- 默认显示一行
- 内容变多后自动增高
- 不堆叠过多选项
- 圆角边框和阴影明确
- 发送按钮使用简单箭头，并有 hover 效果

输入框是对当前作品下达新指令的固定入口。图片、视频和文档上传保持独立可访问入口；视觉可以收敛为白色细边框与低干扰阴影，但不得为了简洁合并或隐藏现有上传、停止生成、上传状态和错误恢复能力。

助手回复里的建议按钮点击后，应该把对应文字放入输入框。除非动作非常明确且安全，否则不要直接静默执行。

缺画面时的逐镜提问是明确例外：编导在确认卡里就缺画面的镜头列出四种做法（我来上传、用图片生成视频、先生成图片再做视频、直接生成视频）和“这一镜先不要”，用户可点选，也可直接用对话说。选择绑定服务端当前编导稿中该镜的结构化提问，再进入费用确认卡，确认前不得生成图片、视频或产生费用。不再向用户提出“关键帧生成建议”，也不在编导阶段生成图片或视频供用户挑选。

创作档案是另一类明确例外：它会产生跨项目长期影响，所以不能沿用普通自然语言调整方式判定接受。候选内容可以由模型从当前项目提炼，但保存、拒绝和关闭必须使用服务端绑定候选 ID 的结构化控件。

## 14. 视频内部制作流水线的界面边界

工作台在服务端只使用五层计划和统一执行图。讲解、真人原视频、原片删留、操作、过程、前后变化和结果验证都由五层组合表达，不加载旧类型策略，也不保留历史读取入口。这些都是后台实现，不增加用户选择类型的步骤，也不改变已经确认的“编导稿 → 确认 → 生成视频工程”主路径。五层中的第五层“逐镜执行”只是每镜实际采用的素材或生成方式，不是分类选项；用户界面只展示每镜的画面来源（你的素材/AI 生成）、来源素材名和进度，不展示“关键帧→视频”“文字直出视频”等生成方式分类，也不能把五层改成必选向导。编导稿阶段仍是文字方案，编导按镜给出画面来源建议（你的素材或 AI 生成，有来源时写素材名），由用户采纳或在对话中修改；不向用户展示生成的图片或视频，确认前不得生成或产生费用。某一镜缺画面时，编导在确认卡里就该镜向用户提问，给出平实的做法让用户选：我来上传（图片或视频片段）、用图片生成视频、先生成图片再做视频、直接生成视频，或这一镜先不要。这四种做法对应用户自己的意图（上传图片做视频、先出图再做视频、直接出视频、基于视频做视频），用用户的话描述，不出现“关键帧”“图生视频”等内部术语。选项只列服务端当前可执行的；用户选定前该镜保持“等你决定”，不自动生成，确认前不得产生费用。公共素材已从产品中取消，不得再作为来源或选项出现。图片与视频是确认后才生成的产物，生成过程只在视频生成进度和分镜胶片条里体现。

视频工程只能由对话中确认当前编导稿进入，不保留从选题直接生成视频工程的旧入口。

- 编导稿、确认卡、进度文案和普通错误提示不显示流水线名、模型、Provider、VLM 或渲染器。
- 用户看到的是分镜内容、画面状态、通用编导稿已公开的创意候选和可执行调整；内部路由、模型候选轮次、检查点与降级过程只进入诊断数据。
- 已持久化的生成画面与已保存素材使用同一分镜预览和编辑交互；历史作品中的公共素材按“历史素材”只读展示，不新增技术类型筛选器。
- 分镜没有经过验证并持久化的主画面时，工程不能显示为可编辑成片；失败提示应可重试，但不伪装成“待补素材”成功态。
- 原播放器外壳、比例、控制条、确认交互和单镜换素材入口保持不变。
- 分镜浏览态可以直接打开单镜配音弹窗；它与胶片条共享同一编辑器和服务端配音任务，不新增第二套旁白状态。
