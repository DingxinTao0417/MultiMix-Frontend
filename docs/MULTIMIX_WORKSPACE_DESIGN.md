# MultiMix 工作台设计文档

状态：待产品确认草案

本文档用于沉淀 MultiMix 独立内容生成工作台的产品定位、页面结构、交互规则和数据边界。

这份内容来自 ChangeIn 资产工作台方向，以及 MultiMix 原型设计过程中已经确认过的产品决策。目标是让独立仓库里的协作者不需要阅读 ChangeIn 原始产品文档，也能理解这个页面为什么这样设计、后续应该怎么扩展。

## 1. 产品定位

MultiMix 是一个内容生成工作台，用来把来源素材、结构化市场信号和已生成产物继续转化为可复用的内容产物。

它不是通用聊天页、社交发布工具、文件管理器、爬虫工具或内容农场。核心价值是帮助用户从有来源支撑的输入出发，生成具体可用的交付物，例如文案、图片方向、短视频脚本、MG 动画草稿、实景视频草稿、数字人口播视频草稿，以及音频和字幕时间轴。

这个页面应该像一个创作工作台：

- 对话负责判断用户意图和生成方向。
- 右侧展示当前选中的生成产物。
- 对话中的产物卡负责切换不同产物。
- 详情、参数、来源链路、素材分配等信息保持在次级层级。

## 2. 核心用户流程

1. 用户从一个历史对话进入，或者新建一个创作对话。
2. 用户用自然语言描述想要生成什么。
3. MultiMix 在对话中生成一个或多个产物卡。
4. 当前选中的产物显示在右侧展示区。
5. 助手在对话中给出简短的下一步调整建议。
6. 用户继续通过自然语言调整产物，而不是进入复杂配置面板。

一个对话里应该支持连续生成多种产物，例如：

- 来源素材包 -> LinkedIn 发帖文案
- LinkedIn 发帖文案 -> 封面图
- 封面图 + 脚本 -> 短视频分镜
- 短视频分镜 -> 数字人口播视频

右侧展示区始终只展示当前选中的产物，而不是同时展示所有历史产物。

## 3. 页面结构

桌面端包含三个主要区域：

- 左侧导航：品牌、搜索、新建创作、资产库入口、对话列表、本地账号信息。
- 对话区：用户消息、助手回复、产物卡、下一步建议、输入框。
- 展示区：当前选中产物的完整内容或预览。

页面应该直接占满整个视口。不应该在工作台上方再显示营销 Banner、积分条、MCP 按钮、账号头像或其他和当前创作无关的主工作台头部。

窄屏时侧边栏可以自动收起。自动收起时，不应该留下空白窄轨道。只有用户主动点击收起时，才需要保留可理解的展开入口。

## 4. 导航和资源库

左侧一级资源入口是：

- `资产库`
- `文案库`
- `视频库`

图片不单独作为一级图片库，而是归属于视频库或具体产物上下文。数字人也不是一级资源库，它属于视频的一种表现形式。

对话列表是观察 Mock 场景和产物链路的主要入口。对话行要紧凑，显示对话标题和最近更新时间。重命名、删除等操作放在 hover 菜单里。

## 5. 对话规则

对话是判断以下内容的主要位置：

- 产物类型
- 发布渠道
- 目标受众
- 内容格式
- 画面比例
- 时长
- 风格
- 语言
- 是生成文案、图片、音频、视频、MG 动画、实景视频，还是数字人口播视频

当对话已经理解用户要生成什么以后，右侧展示区不应该再要求用户选择一级 `文案 / 图片 / 视频 / 音频 / 数字人` Tab。

产物生成完成后，助手回复应该简短说明：

- 生成了什么
- 基于什么内容生成
- 用户接下来可以怎么调整

推荐的自然语言调整建议示例：

- `缩短到30秒`
- `换成9:16`
- `把第2段素材换成产品图`
- `改成数字人口播`
- `字幕更大一点`
- `生成一张4:5封面图`

下一步推荐操作优先放在助手回复里，不要在展示区再做一套独立推荐模块。

## 6. 产物卡和产物切换

当一个对话生成多个产物时，每个产物都应该以产物卡的形式出现在对话流里。

点击产物卡，右侧展示区切换到对应产物。

展示区只显示当前选中的产物。上下游关系可以通过以下方式表达：

- 对话中产物卡的出现顺序
- 产物的简短元信息
- `详情` 抽屉

不要为了切换产物，在展示区再增加强制性的产物 Tab。

## 7. 展示区设计原则

展示区是单一的当前产物工作区。

它应该优先做到：

- 完整展示结果
- 预览不被遮挡
- 图片和视频类产物居中展示
- 减少不必要的 UI 装饰
- 保留轻量标题和状态
- 只在需要时显示 `详情`、`复制`、`保存` 等操作

它应该避免：

- 大面积配置面板
- 围绕结果的大块可见边框
- 重复的推荐操作区域
- 默认展示产物结构卡片
- 来源证据和参数信息占据主区域
- 强制用户切换画布、分镜、时间轴、素材、参数等工作视图 Tab

## 8. 不同产物的展示规则

### 8.1 文案产物

文案产物包括：

- 市场规则内容包
- 政策摘录
- 可复用角度包
- LinkedIn 发帖文案
- 短视频口播稿
- 视频脚本
- 内容方案

处理后的素材包也是产物，不是原始素材。它属于基于来源素材二次加工后的文案产物。

文案产物应该在右侧展示区完整展示，方便用户阅读、复制、保存和后续复用。

默认视图不应该是产物结构面板。如果结构、来源、参数或版本信息有价值，应该放进 `详情`。

### 8.2 图片产物

图片产物包括：

- 封面图
- 分镜图
- 产品场景图
- 社交媒体配图变体

图片预览应该在展示区居中显示。可见边框要尽量少。主区域应该让用户看到图片结果，而不是看到配置表单。

比例、数量、风格、参考素材等轻量控制可以在必要时出现，但大部分调整应该通过自然语言完成。

### 8.3 视频产物

视频产物包括：

- 短视频分镜
- MG 动画
- 实景视频
- 文生视频
- 数字人口播视频

默认展示应该让视频预览居中。只有当时间轴能帮助用户理解或检查结果时，才在主视图里显示紧凑时间轴。

分镜、素材、音频、字幕、时间轴、渲染状态和参数默认放在 `详情` 中。除非这些内容是理解当前结果的必要部分，否则不要直接占据主展示区。

### 8.4 数字人口播视频

数字人是视频的一种表现形式。

它不应该被当作展示区里的一级产物类型。

默认展示方式：

- 中间展示当前数字人口播视频预览
- 下方在必要时展示逐句音频/字幕时间轴
- 不在预览区显示来源证据卡

数字人口播视频只需要知道它使用的是哪一版文案或口播稿。来源证据、生成链路、人设、字幕设置、渲染信息等都放进 `详情`。

如果需要显示口播稿，默认应该折叠或紧凑展示，避免占用过多视频预览空间。

### 8.5 音频和字幕匹配

音频和字幕匹配通常属于视频生产的一部分，不需要单独成为主场景。

它可以表现为：

- 视频下方的紧凑时间轴
- 逐句时间块
- 字幕匹配状态

如果用户专门处理音频产物，也可以使用同一套模式展示波形和逐句时间，但仍然要避免重边框和复杂配置感。

## 9. 详情抽屉

`详情` 是承载有价值但不应该占据主展示区的信息的地方。

它以右侧覆盖抽屉的形式打开，不挤压主预览区域。

详情可以包含：

- 生成依据
- 来源链路
- 来源映射
- 素材分配
- 产物参数
- 画面比例
- 时长
- 风格
- 人设
- 字幕设置
- 口播和字幕匹配
- 渲染状态
- 版本信息
- 上下游产物关系

详情抽屉回答的是“这个产物为什么这样生成、怎么生成的”。主展示区回答的是“我得到了什么结果”。

## 10. 输入框和调整方式

输入框应该有 AI 原生产品的感觉：

- 默认显示一行
- 内容变多后自动增高
- 不堆叠过多选项
- 圆角边框和阴影明确
- 发送按钮使用简单箭头，并有 hover 效果

助手回复里的建议按钮点击后，应该把对应文字放入输入框。除非动作非常明确且安全，否则不要直接静默执行。

## 11. Mock 数据和本地仓库边界

当前独立仓库使用本地 Mock 数据运行。

应该提交：

- 工作台 UI 代码
- Mock 对话和产物数据
- 本地数据库结构
- 本地初始化脚本
- 文档

不应该提交：

- 运行时 SQLite 数据库文件
- `.env.local`
- 生产密钥
- 构建产物
- 日志

本地 Demo 数据库通过以下命令生成：

```bash
npm run setup:demo
```

默认本地 Demo 用户是：

```text
demo@multimix.local
```

SQLite 文件本身不提交。Demo 数据通过数据库结构、初始化脚本和 Mock 源数据共享。

## 12. 后端接入边界

当前仓库是前端优先的本地版本。

后续接入真实后端时，应该保留当前工作台结构，通过替换 adapter 层来接入真实数据，而不是因为后端实现方式重写 UI。

未来可能接入：

- Supabase Auth：真实用户登录
- Supabase Postgres：持久化对话和产物
- Supabase Storage 或其他存储：保存文件和生成媒体
- Railway API：编排生成任务
- Worker 服务：处理长时间运行的图片、视频、音频任务
- 渲染适配器：对接视频和数字人生成服务

前端不能包含 service-role key、Railway token、Vercel token 或生产密钥。

## 13. 当前需要保留的设计决策

- MultiMix 是独立内容生成工作台。
- 对话决定产物类型和生成意图。
- 展示区直接显示当前产物。
- 展示区不增加一级产物类型 Tab。
- 数字人属于视频模式。
- 音频和字幕匹配通常属于视频。
- 文案产物也进入右侧展示区。
- 素材包是生成后的文案产物，不是原始素材。
- 详情信息放进抽屉。
- 下一步推荐操作放在助手回复里。
- 对话中的产物卡负责切换右侧展示。
- 本地运行数据库不提交，通过可复现 Mock 数据生成。

## 14. 待确认问题

在从原型进入生产化之前，需要继续确认：

- MultiMix 是否保持纯独立产品，还是同时保留作为 ChangeIn 子工作台的部署方式？
- 哪类产物优先接入真实持久化：文案、图片、视频，还是数字人口播视频？
- 本地 Mock 产物是否需要从 TypeScript fixture 迁移成 JSON seed？
- V1 最小可用的 `详情` 抽屉应该包含哪些内容？
- 哪些生成适配器是 V1 真实可用的，哪些只显示草稿或暂不支持状态？
- 什么情况下算作保存了一个产物版本？
- 点击建议按钮是只填入输入框，还是允许某些明确按钮直接执行？
